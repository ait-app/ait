# 桌面、Android 与 iOS 统一登录

## 服务端准备

先发布配套 `ait-server` 后端和 Web 控制台，运行 `0008_authing.sql`。保持原有 Authing HTTPS 登录回调配置；桌面的回环地址和移动端的应用链接由 AIT 中心处理，无需加入 Authing 应用回调白名单。

检查实际服务地址：

```sh
curl https://dash.ait-app.com:8443/api/v1/auth/providers
```

响应须包含 `authing_enabled: true`、`native_login_enabled: true`。客户端不填写 App ID 或 App Secret，开发环境可在「在线服务 → 服务设置」填写对应 API 地址，例如 `https://ait.h.stdin.in:8443/api`。

## 用户流程

1. 在「在线服务」点击「登录 / 注册」，桌面与 Android 打开系统浏览器，iOS 打开系统认证窗口，随后进入 Authing 页面。首次使用 iOS 可能需要同意系统显示的认证提示。
2. 完成手机号验证码、邮箱、Google 或微信登录。注册、手机号/邮箱验证和密码找回在托管页面完成。
3. 浏览器显示当前邮箱或手机号，点击「确认并返回客户端」。iOS 的认证窗口自动关闭并回到客户端；Android 如未自动唤起，点击页面上的「返回 AIT」。
4. 客户端保存 AIT 会话，显示账户有效期并加载在线主机。新账号默认创建 7 天后到期，管理员续期后可重新登录。

Desktop 登录后默认将内置 daemon 注册到在线服务。若在该主机的「连接」设置中停止同步，重启或重新登录后仍保持下线，直到手动重新开启同步。其他主机继续手动启用同步，详见 [ADR-096](../decisions/clients/adr-096-desktop-default-host-sync.md)。

同邮箱已有旧账号时，先使用原密码登录 Web 控制台，在设置里绑定统一登录；绑定保留原 Host、角色和有效期。客户端保留「使用原 AIT 密码登录」入口。

客户端退出保持已有逐主机同步语义，不等同于中心的全会话注销。详情见 [ADR-086](../decisions/clients/adr-086-authing-native-login.md)。

## 登录保持（2026-10-10）

配套中心将网页、桌面、Android、iOS 的用户登录上限延长到 14 天，仍受 Authing ID Token
和本地账号有效期限制；登录不会续客户有效期。Authing 的 `id_token` 配置为 `1209600` 秒，
中心和网页发布后需重新登录一次取得新期限。已有 JWT 不会自动延长，本次无需新增数据库迁移。

桌面和移动端继续使用系统安全存储。关闭应用不会删除或重写已有凭据，主动注销仍会清除；
桌面没有可用安全存储时只能保持本次进程登录。网页使用持久存储，关闭浏览器后可以恢复，
启动断网保留凭据并在重载页面后重试。当前未实现用户会话自动续期，细节和验证结果见
[Relay 登录保持](../plans/relay-client-session-persistence.md)。

验收时分别检查四端登录后立即重开、隔夜重开、断网启动后恢复网络，以及主动注销、账号到期
和中心撤销后的重新认证。网页另外检查关闭全部标签页后重开；账号只有 7 天有效期时，应按
账号期限失效，不应获得完整 14 天。
在在线主机列表中明确添加的主机会保存到客户端主机注册表。重启后先显示已保存的主机；账户恢复上线后，自动连接同一服务下的已添加主机。登出、离线或切换服务保留记录。主机设置中的删除操作移除本地记录；账户界面的断开只移除该主机在当前服务下的中继连接，已有直连配置保留。切换主机可以同时保留多台连接，发现列表不会自动导入，见 [ADR-122](../decisions/clients/adr-122-persistent-online-service-hosts.md)。

## iOS 构建

iOS 使用新增的 `expo-web-browser` 原生模块，必须重新生成并安装开发包或 TestFlight 包，单独更新 JavaScript 无法给旧包添加模块。沿用仓库 [Apple 本机构建](apple-builds.md) 或 [EAS 发布流程](releasing.md)，自动链接该模块；Expo 配置保留 `scheme: "ait"`。使用现有原生工程的开发者需更新 Pods 后重建。无需新增 Authing 应用、回调白名单或数据库迁移。

## 联调验收

- 安装新版桌面、Android 与 iOS 客户端，分别完成手机号无邮箱、邮箱、Google、微信登录及新账号注册。微信需提供已验证手机号或邮箱。
- 验证取消、超时、用户关闭浏览器、移动端切到后台再返回、应用进程被结束后的重新登录。iOS 还需验证系统拒绝认证、取消认证窗口后重试，以及邮箱、Google、微信的实际回传。
- 验证旧密码登录、旧账号显式绑定、主机发现与访问，以及账户到期后的续期提示。
- 登录尝试、一次性代码和 verifier 不得写入日志；客户端只持久保存 AIT 会话。真实 Authing、系统浏览器唤起和安装包回传需在对应设备上验收，模拟测试不替代此步骤。

## Test coverage

此次客户端只修改 TypeScript/React，无 `bins/` 或 `crates/` Rust 行为变更，Rust 覆盖率不适用。TypeScript 行覆盖率未测量；本地迭代运行共享会话、桌面回环回调、Android URL 回调、iOS 认证窗口的成功/取消/异常/错误 state、后台返回后的安全存储与登录界面的定向测试。真实提供商和设备端到端路径仍需按上述清单验收。

## 手机号账号兼容（2026-10-10）

共享账户管理器接受 `user.email: string | null` 和可选 `user.phone_number: string | null`。展示优先使用非空显示名称，再用邮箱或手机号；无有效联系方式的响应仍被拒绝。桌面、Android、iOS 复用该实现，PKCE、持久会话、过期时间和主机同步保持原流程。`contact_verification_required` 提示用户验证手机号或邮箱，同时保留旧邮箱错误码兼容。

手机号验证由 Authing 和中心负责，客户端不发送短信、不把显示名称或手机号当成认证凭据，也不按号码合并账号。没有邮箱的用户使用统一登录；原 AIT 密码入口继续使用邮箱。

先发布本次客户端兼容改动，再发布支持手机号账号的中心和 Web（迁移 `0011_phone_login.sql`），并确认 Authing 的短信服务、手机号登录及 OIDC `phone` scope 配置。旧客户端会拒绝 `email=null` 的登录结果；新客户端继续兼容原邮箱账号和旧中心。产生无邮箱用户后，旧中心无法读取这些用户，不能直接回滚服务端。

真实联调需确认验证码登录后的 `phone_number_verified=true`、手机号无邮箱注册与重复登录、浏览器确认号码、取消/重试、旧账号显式绑定、主机发现，以及账号停用/到期/撤销。自动化覆盖共享账户保存与主机发现、无效响应拒绝和错误说明；不代表已验证真实短信或设备唤起。
