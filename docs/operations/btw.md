# BTW 侧会话

在已有 Agent 的输入框输入 `/btw` 打开侧会话，或输入 `/btw 问题` 直接提问。
主会话执行中也可使用。窗口中的问答独立保存，不进入主对话或主输入队列。
窗口沿用 Ait 的主题强调色、语义颜色、字体、间距、圆角和阴影，随主题及用户字号、字族设置变化。
行内 `$...$` 与独立 `$$...$$` 公式使用共享 Markdown 数学引擎；Web/Desktop 本地排版，
无需外部公式服务，字体大小与颜色沿用正文。移动端数学模块随原生 App 重新构建启用。

## 对话与窗口

- 桌面与 Web 使用浮动聊天窗口，仍可操作背后的主会话；窄屏自动适配。
- 第一次提问冻结当时已保存的可读主上下文和所选 provider、模型。
  在同一话题继续输入就是追问，沿用这份上下文与已有问答；主会话后来的变化不会混入。
- 停止只取消当前 BTW 回答。关闭运行中的窗口会先确认取消，再关闭；失败保留窗口供重试。
  关闭保留已保存的历史，之后显式输入 `/btw` 可重新查看。
- 使用窗口中的历史选择已有话题，或新建话题重新取得当时的主上下文。
- 展开按钮把当前话题带入一个新的完整会话草稿，包括冻结的主上下文和 BTW 问答。
  展开本身不调用模型；用户发送下一条消息时，按普通会话继续工作。原主会话和侧话题均保留。

上下文来自显示 Timeline，不能复制原生隐藏推理、工具内部状态或未保存内容。
投影和上下文有明确预算，裁剪会标记；展开使用保存的完整话题，而非仅取窗口中的预览。

## Provider 接入

BTW 的窗口、RPC、持久化、追问、取消和展开由 Ait 统一处理。
每个 provider 的原生命令和隔离执行由 adapter 实现同一个 `SideQuestions` 端口。
有原生 `/btw` 且能通过机器接口调用的 provider，可沿此端口接入而无需修改前端。
仅在 TUI 里能输入同名命令，并不保证远程接口也能执行它。

| Provider                               | 执行方式                                                             |
| -------------------------------------- | -------------------------------------------------------------------- |
| OMP                                    | 独立辅助进程调用原生 BTW RPC                                         |
| Codex                                  | 独立辅助 app-server thread，按侧问答规则隔离执行                     |
| Claude Code                            | 独立无工具执行，禁用 MCP、hooks 和原生 session 持久化                |
| Pi                                     | 独立无 session 的 RPC 进程，禁用工具、扩展、MCP、skills 与上下文文件 |
| OpenCode                               | 独立私有原生 server 的无 session 文本生成 API；回答完成后一次返回    |
| DeepSeek Harness、Antigravity、MiniMax | 当前未接入此端口；不把 BTW 输入交给主会话执行                        |

执行器只选当前 provider 的 adapter。原生接受不明确时保留收据并核对事实，不自动重发、
切换 provider 或改成普通主会话提示词。原生版本、可执行文件或隔离能力不可用时显示错误，
历史仍可读取；旧 daemon 缺少侧问答 RPC 时显示不支持。

目前这些辅助执行要求 Unix Host 的进程组能力，可用性在所连接的 Host 上探测。

OMP 沿用原生 BTW 的工具描述目录以兼容要求非空 `tools` 的模型接口；原生 BTW
消费单次模型输出并丢弃工具调用，不进入工具执行循环。辅助进程仍禁用扩展、skills、
rules 与上下文文件。OMP 18.17 的真实二进制已用本地恶意工具调用响应验证：只有一次
模型请求，无工具执行、无工具结果轮次，且主原生日志保持为空。

## 真实 Tai 验收

2026-11-13 在 Linux 上使用新构建的独立 Host 和实际 Ait Web 界面，主模型为
OMP 18.17.0 的 `tai/deepseek-v4.1-flash`，推理连接本机已配置的真实 Tai API。
编程任务在独立 Git 项目完成，输入为公开合成的脱敏 JSONL 样本；未使用模拟模型。

- 实现日志汇总 Rust CLI，独立复跑 23 项测试及 8 条记录的 CLI 示例，全部通过。
- 继续实现 `--provider` 精确过滤，最终独立复跑 38 项测试及过滤示例，全部通过；
  匹配 3 条、跳过 5 条，错误与取消各 1 条，平均耗时 1950ms、p50 1230ms、p95 4500ms。
- 主任务执行期间，同一 BTW 话题完成首次回答和追问，策略均为 `native`；主 Timeline
  不含侧问题。关闭、重开及浅色/深色主题切换通过。
- 展开保留冻结上下文和两轮问答，只生成完整会话草稿；首次发送前没有新 Agent 或推理。
- 首次发送后仅创建一个新的 Tai 完整会话，实际编辑 README/report 并运行 38 项测试通过；
  原主会话未重新执行，原侧话题保留。
