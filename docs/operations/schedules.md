# Workspace 定时任务

在 Workspace 的新建菜单中选择“定时任务”，打开工作区任务列表。每个 Workspace 只有一个定时任务标签页，
再次打开时显示已有标签页并保留其当前视图。列表按下一次触发时间从早到晚排列，
并按今天、明天和日期分组，每页最多 20 个任务；点击条目直接编辑，列表末尾的“新建定时任务”按钮用于创建，保存或取消后返回列表。
任务始终属于当前 Workspace，可选择该工作区内未归档的已有 Agent，或每次运行时创建新 Agent。新 Agent
使用当前工作区的实际目录；需要隔离工作目录时，在对应的 Worktree Workspace 创建任务。

表单通过单个“执行 Agent”选择器完成选择：顶部是“每次运行时新建 Agent”，下方直接列出
当前主机、当前 Workspace 内未归档的 Agent，可按名称搜索。点击现存 Agent 即完成绑定；
选择新建时才显示模型等创建配置。在两种方式间切换会保留提示词和已选择的新 Agent 配置。

左侧 Schedules 页的新建入口先选择 Host，再选择该 Host 的 Project，最后选择项目内的 Workspace。
位置确定后显示与 Workspace 标签页相同的任务表单，运行次数仍默认 1。位置选择保留在表单顶部；
更换 Host 会清空 Project、Workspace 和任务草稿，更换 Project 会清空 Workspace 和任务草稿。
提交期间锁定位置选择。任务使用所选 Workspace 的实际目录，包括 Worktree 目录。

全局列表查看全部 Host 时，任务行显示主机名；筛选到具体 Host 后省略行内主机名。
只有一个 Host 时同样省略，任务的 Workspace 和执行目标仍显示。

## 从模板开始

新建任务先展示模板库，按“代码与协作 / 主题订阅 / 项目维护”分组；桌面双列卡片，窄屏单列。
卡片分别显示用途、执行时间和所需能力，底部统一标明设备时区。“从空白开始”进入空白配置。
选择模板后填入名称、提示词、Cron 规则并清空运行次数（不限）；字段仍可修改，执行 Agent、模型和位置保持当前选择。
主题简报先填写简报主题，再点击“填入任务”进入编辑；参数面板随后收起，主题已经写入提示词。

编辑页分为“内容与时间”和“执行与限制”：前者编辑名称、提示词与触发规则，后者设置执行 Agent、模型、
首次触发、截止时间与运行次数。切换分区或返回模板库保留当前填写内容；再次应用模板会覆盖名称、
提示词、触发规则和运行次数。Workspace 内的创建按钮固定在底部。已有任务直接进入编辑，不展示模板库。

| 模板           | 触发规则        | 用途                                               |
| -------------- | --------------- | -------------------------------------------------- |
| 测试检查与修复 | 每天 02:00      | 按仓库要求运行测试，在独立分支修复有明确依据的缺陷 |
| PR 风险审查    | 工作日 10:00    | 审查近 24 小时更新的开放 PR，附失败场景与验证建议  |
| 主题简报       | 工作日 09:00    | 查阅主题的一手资料，整理最多五项进展，需要网页检索 |
| 工作区周回顾   | 每周五 16:00    | 根据近七天的提交、PR 和项目记录整理进展回顾        |
| 文档一致性检查 | 每月 1 日 10:00 | 对照实现核实命令、路径和示例，给出有依据的修正建议 |

模板只存在于客户端，提供中文、英文、日文和韩文文案，其余界面语言使用英文模板。
创建出的任务与手动填写的任务相同，daemon 不记录模板来源。
测试检查与修复遵循仓库指引中的测试范围和交付权限；会修改代码，建议在 Worktree Workspace 中创建。

## 时间和限制

- 固定间隔：填写正整数与毫秒、秒、分钟、小时或天。默认在一个间隔后首次运行；可指定首次触发时间。
- 日历 / Cron：使用五字段表达式与 IANA 时区。默认使用设备时区，可从预设开始修改。
  首次触发时间是最早允许触发的时间，实际触发仍需匹配 Cron。
- 截止时间：可选，超过该时间不再接纳自动或手动运行。
- 运行次数：默认预填 1，表示只运行一次；填写更大的正整数按周期重复，留空表示不限。
  单次不是独立的触发选项。成功、失败和手动运行均计入次数。

时间输入使用 `YYYY-MM-DD HH:mm`，按设备本地时区解释；Cron 使用单独设置的时区。
间隔按照真实经过时间计算，不会转换成近似的 Cron。新建任务默认等待触发时间，
需要测试时可在详情中点击“立即运行”。运行次数为 1 的任务在首次手动或自动运行结算后结束。

## 管理

创建或编辑保存后返回列表，默认展示即将执行的任务；可切换查看已暂停或已结束任务。
每个条目展示下一次触发时间；运行历史入口可查看输出、打开 Agent，并执行暂停/恢复、
立即运行或删除。编辑视图、列表筛选和详情可随标签布局恢复，当前页码不随布局保存。
旧布局中的多个定时任务标签页在恢复时合并为按窗格顺序的第一个。
关闭标签页不会删除任务。

全局定时任务列表在未结束且目标可用的任务旁直接显示暂停或恢复按钮，两种执行 Agent
目标均可操作；右侧菜单也保留暂停/恢复入口。请求处理中禁用重复的状态操作。

暂停阻止后续自动触发，已接纳的运行继续执行。任务运行期间可以暂停；编辑目标与删除
需等待本次运行结束。达到次数上限、超过截止时间、目标永久不可用或 Cron 不再有可触发时间时，任务结束。
选择“每次运行时新建 Agent”后，可在“执行与限制”的“运行结束后”选择“在工作区保留会话”或
“归档会话”（默认）。保留时，每次运行创建的会话都会留在所属 Workspace，可查看结果并继续对话；
即使运行次数为 1、任务已结束，会话也不会自动归档。重复运行仍会每次创建新会话；需要复用同一
会话时，选择已有 Agent。所属 Workspace 始终保留。

运行中提交包含执行目标的更新请求会返回 `schedule_running`，表单提示：
“任务正在运行，请等待本次运行结束后再修改。”

已有 Agent 目标的每次运行把提示词包在 `<ait-input kind="schedule" …>` 信封中发送，时间线显示任务名与运行 ID；
新建 Agent 目标仍直接发送提示词，使其中的 slash 命令照常生效。调度由主机上的 daemon 执行，客户端可以关闭。daemon 停止或主机离线时不执行任务。
重启后，已接纳但未结算的运行记录为失败，周期任务跳过过去的触发点；旧格式 `once` 中尚未接纳的触发会补执行一次；当前以次数控制单次的周期任务仍跳过
过去的触发点，按下一个周期运行。单个任务不会重叠运行；Agent 忙碌或等待权限时，本次运行记录为失败。
当前存储最多保留每任务 4096 次运行，达到该容量时任务结束；每次输出最多保留 64 KiB。

## 旧任务和接口

全局定时任务页保留所有主机的任务，也显示旧版未绑定任务。编辑旧任务时选择具体
Workspace，保存后获得固定归属；不会根据目录自动分配 Workspace，历史运行位置也不会改写。

旧格式 `once` 在编辑界面显示为触发时间和运行次数 1。仅修改名称或提示词会保留原规则；
改变时间、周期或次数时转为周期规则，并保留未改动触发时间的原始精度。

新建接口要求 `workspaceId`；`schedule.list.request` 接受可选的同名过滤字段。
更新接口支持 `target`、`startAt`，以及旧版 `newAgentConfig` 补丁，但 `target` 和
`newAgentConfig` 不可同时提供。已绑定的 `workspaceId` 不能修改。详细边界与持久化版本
兼容性见 [ADR-138](../decisions/workspace/adr-138-workspace-owned-schedules.md)。
