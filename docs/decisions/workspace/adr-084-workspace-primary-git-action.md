# ADR-084：工作区主按钮按提交与 PR 生命周期推进

- 状态：Accepted
- 日期：2026-10-05
- 关联：ADR-066、ADR-069、ADR-083

## 背景

工作区右上角按钮需要提示当前工作的下一步。工作区干净、旧 PR 已合并，并不能证明当前 HEAD 已交付；同一分支可能已经开始下一轮修改。空实验工作区也不应该默认推荐归档。

## 决策

1. 本地未解决冲突、同名远端分支落后或分叉时，主按钮显示对应的禁用状态。正常流程为“提交工作区”→“创建 PR”→“推送”→“查看 PR”→“归档工作区”。打开的 PR 有待推送提交时，主按钮使用已有的“推送”动作和文案；“查看 PR”只打开链接，不负责推送。PR 与目标分支冲突不阻止推送源分支。PR 合并和 auto-merge 操作保留在菜单中。
2. Checkout adapter 提供可选的 `branchStatus`，包含 `headSha`、`hasConflicts`、`remoteRef` 和 `aheadBehind`。比较对象是优先远端上的同名分支；`upstreamRef` 和旧 `aheadOfOrigin` / `behindOfOrigin` 的语义继续保持为实际配置的 upstream，供手动同步操作使用。无同名远端引用时，引用和数量保持 `null`，不伪造零值。
3. Forge adapter 提供可选的 PR `headSha`。打开的 PR 可查看；当前分支有待推送提交时，主按钮提示推送。关闭或合并的旧 PR 与当前 HEAD 不匹配、且当前分支仍有可交付提交时，主按钮重新推荐创建 PR。
4. 创建 PR 沿用先推送再创建的服务端流程。打开的 PR 有待推送提交时，主按钮直接调用现有 `checkout.push.request`，与其他 Push 使用同一目标选择、执行状态和提示；协议不提供 PR 专用的推送目标设置。
5. 推荐归档要求 Git 与 PR 状态已知、工作区干净且无冲突、PR 已合并、源分支与当前分支和提交一致、同名远端分支无差异，并且 Agent 目录已加载且工作区无活动 Agent。初始化、运行状态、打开的 turn 和待处理授权都视为活动，包含子 Agent。远端分支已被删除时，只在当前提交匹配已合并 PR 的源提交时允许推荐归档。
6. 目标分支前进或 squash / rebase 合并造成的历史差异不阻止归档。客户端不依赖曾经执行合并的本地布尔标记，也不将空闲工作区默认提升为归档。
7. 左侧与下拉菜单的手动归档保留原有风险确认行为。没有主按钮时，右上角仍显示菜单入口。

## 后果与验证

新事实字段可缺省，旧服务端缺少事实时不会推荐归档，干净工作区显示状态未知。Rust 本地 Git 测试覆盖同名分支与 upstream 不同、分叉、删除分支、冲突和显式推送目标；客户端回归测试覆盖 PR 生命周期、状态未知、活动 Agent、翻译和无主按钮时的归档入口。
