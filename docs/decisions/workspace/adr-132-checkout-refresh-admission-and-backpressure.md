# ADR-132：Checkout 刷新独立准入与有界输出背压

状态：Accepted
日期：2026-10-11

## 背景

Changes 刷新、状态和 diff 初始读取使用全局 `jobs`，后台 diff 轮询使用独立额度但
仍锁住同一个 Checkout。等待 Git 锁的前台读取会长时间占用全局额度，使其他能力返回
`resource_exhausted`。反向竞争也会使 Changes 刷新在已有后台任务时被拒绝。

单条结构化 diff 已有输出大小检查，但同时入队的两个合法快照仍可能超过连接的
4 MiB 总预算。同步 `Outbound::send` 在这种短暂拥堵时取消连接，客户端只能看到断线。

## 决策

- `model::Runtime` 给前台 Checkout 操作独立的单任务额度；已通过连接准入的请求排队
  等待，执行仍经过同一个 Checkout 锁、阻塞任务跟踪与关闭检查。后台轮询额度保持独立。
  等待或执行 Git 操作不再占用目录、Provider 和其他功能的全局 `jobs`。
- `model::outbound::Outbound::send_waiting` 对 JSON 复用二进制输出的有界背压实现。
  Checkout 成功响应和 diff 更新等待已有输出预算；不新增缓存队列或增加字节/消息上限。
  在途帧继续持有预算，直到物理写入完成。等待者不提前占用不足的字节，避免单连接中的
  大 diff 等待挤掉小型 Ping/控制响应；实际帧释放预算后统一唤醒。超出单帧预算立即拒绝，
  断线与取消结束等待。
- diff 订阅在释放或服务关闭时取消输出等待，停止生产后续更新；初始响应成功交付后
  才激活订阅。其他调用点继续沿用原有输出策略。

## 后果与验证

正常拥堵产生等待，不再把合法 diff 的累计体积视为连接故障。慢接收端仍受现有物理写入
超时与输出预算保护。繁忙 Git 操作仍可能延迟 Changes，但不挤占其他功能的工作额度。

测试分别覆盖真实 WebSocket 下的繁忙任务刷新与同连接 Ping/后续状态读取、JSON 在途字节
和消息数背压、连接关闭与取消，以及已启动阻塞任务的生命周期。默认四连接与在线服务
单连接协议使用同一 Checkout 实现；本决策不变更客户端协议或身份鉴权。
