# ADR-109：本地故障证据与 Harness 日志采集

状态：已接受

日期：2026-10-08

修订：证据文件存储由 [ADR-112](adr-112-persistence-crate.md) 迁至 `bins/daemon/src/diagnostics/store.rs`。

## 背景

应用诊断只有状态快照和桌面日志尾部。用户复制长报告难以分享，开发者需要再次索要
Harness 版本、日志目录与故障时间段。只看 Ait 的错误码不足以定位原生程序故障。

## 决策

- 保持 `diagnostics.request` 的 `{ diagnostic: string }` 返回契约，兼容现有客户端。
  metadata 的 daemon 服务依赖 `DaemonDiagnostics` 端口；daemon 组装本地实现。
  按 ADR-100 使用完整 metadata 服务装配，按 ADR-106 将证据文件读写与保留放在 `file` crate。
- Provider 继续拥有原生程序和日志目录发现。`provider::diagnostics::HarnessEvidence`
  只读查询版本与日志，原始内容仅传给 daemon 的脱敏器，不直接返回客户端。
- daemon 的 tracing Layer 接收 WARN/ERROR，统一 RPC 错误出口记录安全错误码和请求 ID，
  Provider 原生操作和失败回合记录安全类别。回调只更新有界内存并非阻塞投递，
  后台线程执行探测、文件读取、脱敏和保存。
- 自动采集按 30 秒窗口合并；窗口内后续错误留在 128 项环形记录中并补采，覆盖损失与
  队列丢弃计数进入报告。手动诊断缓存 30 秒，并附带最近 3 份已保存证据。
- 每次捕获故障前 5 分钟到采集开始的 UTC 日志；有明确偏移的时间先转 UTC。
  无时区的 ISO 时间按 UTC 解释，并在报告中说明。无时间戳的行不冒充相关上下文。
- 每个来源最多检查 1024 个目录项、读取最新 3 个普通日志文件，每个只读最后 64 KiB。
  不递归扫描、不跟随目录内符号链接、不读取会话 JSONL、凭据或配置文件。
  命令不经过 shell，输出最多 4 KiB、探测超时 2 秒；缺失、超时、截断明确标注。
- 脱敏先于落盘；单份证据限制 256 KiB。Ait 只清理自己命名的证据文件，保留期限为
  7 天、20 份、总计 5 MiB，任一上限触发清理。启动、周期维护、写入和手动导出前执行。
  不修改 Harness 的原始日志。Unix 证据目录和文件分别限制为 0700、0600。
- UI 提供文本附件导出；桌面/Web 下载，移动端系统分享并删除临时副本。复制功能保留。
  不自动发送到 GitHub 或其他远端。

## 后果与限制

现有依赖方向不变，daemon 承担本地证据生命周期，Provider 保留原生日志知识，客户端只
处理格式化后的报告。连接延迟探测失败不再阻止 daemon 诊断。

采集是有界尽力取证，不保证所有原生日志格式均可解析，也不截获未记录的错误、所有
子进程 stderr、前端崩溃或操作系统强杀前尚未写盘的数据。文本脱敏采用保守敏感行删除
和位置隐藏，不能证明自由文本中绝无敏感内容；分享前仍可查看报告。
DSH / Antigravity 未假设稳定日志位置，需要显式目录配置；版本探测使用 CLI，无法探测
的桌面内置运行时会明确显示 unavailable。日志目录应位于本地磁盘，网络文件系统卡顿
可能使后台采集延迟，但不会在 tracing 回调中阻塞主请求。

配置与操作见 [故障诊断](../../operations/diagnostics.md)。
