# ADR-120：单连接启动请求的有界排队

- 状态：Accepted。
- 日期：2026-10-10。
- 修订：[ADR-074](../clients/adr-074-account-host-relay.md)的单连接入站槽位数量。

## 背景

桌面启动会在首个响应前发送多个目录、终端和 Workspace 查询。单连接协议每个能力组只有
两个入站槽位，遇到尚未完成的文件或 Provider 操作时，正常查询突发即返回
`ResourceExhausted`。客户端的有限重试可能在该操作完成前耗尽，留下未建立的订阅和空视图。

0.0.25 原版在空数据目录下通过 `connection.single.v1` 同时发送 30 个只读请求，
21 个返回资源错误；旧的逐条读取协议不会暴露这一队列问题。

## 决策

API 继续拥有物理连接、四个能力组队列和组内顺序，每组队列容量改为 16。执行资源、服务锁、
原生会话生命周期仍归原所属组件。队列容量不改变全局任务准入、订阅数量、出站字节预算、
分块组装预算或文件 ACK 背压。

超过组内队列容量的 RPC 继续返回可重试资源错误；事件或二进制消息不能进入队列时仍结束
连接，避免静默丢失输入。Ping 继续在路由层处理，无须等待忙碌的业务 worker。

## 后果与验证

正常启动突发能够等待前一项操作完成。每条物理连接的普通入站队列最多 64 个消息，
相较原先的 8 个消息占用更多内存；普通帧仍受 1 MiB 限制，大消息仍持有分块组装许可。
资源错误依然表示超出有限接纳能力，不自动重放写操作。

回归测试在一个等待任务预算的文件 worker 后发送 10 个目录请求，要求它们按序成功且
Ping 立即可用；32 个请求的超量突发必须触发资源拒绝，已接纳请求仍完成。
本机验证见[崩溃与启动失败修复报告](../../reports/daemon/daemon-startup-panic-fix-2026-10-10.md)。
