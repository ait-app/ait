# ADR-200：Headless 独立维护 Hub、Relay 与节点租约

> 启动与控制边界已由 [ADR-201](adr-201-daemon-owned-publication.md) 修订：所有 daemon 自主发布，外部可暂停 Hub。

状态：采用。修订 [ADR-180](adr-180-hub-serve-endpoint.md) 的 headless 发布调度与端口默认行为。

## 背景

`StatusRelay` 包装 `api::ManagedRelayHandle` 时漏转发 Hub 方法，继承的 `hub_active()` 默认返回 `true`，导致实际 headless 启动不申请 Hub 票据。控制器还先申请 Relay 票据再启动 Hub；Relay 出错会跳过 Hub，任一取票请求耗时较长都会占住续租循环。

## 决定

- daemon 的 `StatusRelay` 显式转发 Hub 启动和状态查询。`ManagedRelay` 的这两个方法不再提供默认实现，新增包装器漏接时由编译器报错。中心侧 `hub_ticket` 仍允许默认返回 `Unavailable`，兼容不支持 Hub 的中心。
- `host-link` 的授权循环继续独占凭据轮换、持久化、节点注册和续租。它通过进程内 watch 发布当前有效授权；传输循环只使用短期 JWT 申请票据，实际 Relay/Hub 连接器只接收一次性票据。
- Relay 与 Hub 各自维持连接。两条循环与授权循环在同一 controller 内并发运行，不产生脱离 controller 生命周期的任务。Relay 网络或协议失败按 1、2、4 秒递增退避，最多 30 秒；Hub 不可用或协议不兼容后等待 60 秒。每次状态检查、取票和启动尝试合计最多 10 秒，慢请求不阻塞另一条链路或续租。
- 普通续租不取消在途取票。授权代次在 JWT 更新、会话替换或本地授权失效时变更；旧请求随授权变化取消，过时代次的错误不能影响新授权。节点仍按既有约定在 `replaced` 后让出 Hub 链路。
- 任一取票接口明确报告授权撤销、会话过期或运行实例冲突时，交回授权循环统一处理。授权失效时关闭两条链路；会话过期重新注册；实例冲突等待原租约释放。Hub 的可选能力与协议失败保持局部退避。
- 授权循环优先于传输循环被轮询，等待时间不能跨过本地授权截止时间。取消、租约过期或终态错误时，先撤销在途工作再关闭传输，避免同一截止时刻返回的旧票据重新启动链路。
- `running` 表示节点授权和租约有效，不保证两条物理连接同时在线；连接状态仍由各连接器提供。Relay 继续支持文件下载与旧客户端回退，Hub 可以在 Relay 故障时独立上线。

## 验证

- `host-link` controller：Relay 取票失败恢复、双向慢取票隔离、超时后重试、Hub 断线重连、续租不受影响。
- 授权边界：租约截止时的迟到票据、会话替换、取票撤权打断在途续租、关停取消在途请求，以及既有凭据轮换和存储失败测试。
- daemon headless 组合测试：真实 `StatusRelay` 的 Hub 初始状态、非法票据、启动转发与关闭；本地服务可用性与存储锁释放。
