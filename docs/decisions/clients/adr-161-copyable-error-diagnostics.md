# ADR-161：客户端统一错误提示与可复制诊断

- 状态：Accepted
- 日期：2026-10-19
- 延续：ADR-144、ADR-049

## 背景

客户端错误分散在 Toast、内联提示、原生 Alert、Query/Mutation、Provider 时间线和渲染兜底中。
只展示字符串会丢失异常 cause、stack 与 RPC 身份，错误 Toast 自动消失也不利于反馈问题。

## 决策

1. 共享客户端 UI 的 `diagnostics/error-reporter` 持有进程内的有界诊断记录。记录包含发生时间、
   来源、异常原因链、AggregateError、堆栈、结构化上下文和近期 WARN/ERROR 日志。
   最多保留 50 条错误及 80 条日志，每条详情限制 32 KiB，日志条目限制 8 KiB。
   相同异常身份或两秒内相同消息去重；异常对象本身仅通过 WeakMap 关联，不写磁盘。
2. 应用入口在路由和运行时初始化前安装采集。保留并调用原 console、浏览器错误事件及
   React Native ErrorUtils 处理器；Query/Mutation 和 Provider `turn_failed` 主动进入相同入口。
   原生错误对话框改用跨平台错误提示；权限请求、确认和正常取消保持各自语义。
3. SDK 在请求失败时记录 serverId、requestId、requestType 和异常，不记录请求参数。
   SDK 的结构化日志保留非枚举 cause/errors。协议字段和 Rust 领域边界保持现有归属。
4. 错误 Toast 排队显示，手动关闭，不被成功提示覆盖；Android 错误不使用无法承载操作的
   系统 Toast。Toast、共享内联 Alert、Provider 失败条目、启动错误和根渲染兜底提供
   “复制错误日志”与“导出日志”。根兜底不依赖 ToastProvider。
5. 日志收集在按钮出现后后台执行，同一错误共享收集任务；只读客户端快照及桌面应用/
   daemon 日志尾部，不因错误再发诊断 RPC。日志读取两秒超时、部分失败或运行时不可用时，
   原始错误报告仍可复制。较早点击会取得当时已经收集的报告。
   浏览器剪贴板访问从点击回调直接开始，失败时保留原报告并提示使用文件导出，避免递归报错。
6. 缓存和导出前脱敏密码、Token、Authorization、Cookie、URL 认证信息及主机连接凭据；
   完整导出限制 256 KiB。设置中的现有应用诊断报告同时包含近期错误记录。

## 后果

桌面、Web 和移动端共享同一错误记录及复制行为。前端原因链与请求身份可用于定位后端日志；
桌面可自动附带本地日志尾部，Web/移动端不读取远端 daemon 的原始日志文件。
错误报告只在当前客户端进程内保留；Provider 已持久化的错误时间线继续沿用 ADR-144。
输入校验、用户取消及正常工具执行结果不转换成全局应用异常。

## 验证与 Test coverage

定向测试覆盖异常链、请求关联、去重与内存边界、敏感信息脱敏、平台错误处理器保留、
Query/Mutation 失败、错误队列、渲染兜底、剪贴板失败和导出、日志读取失败及超时。
覆盖率未测量：用户未请求覆盖率；如需测量，限定共享 SDK 和客户端诊断相关用例。
本次未修改 Rust 实现，不运行 Rust 测试。
