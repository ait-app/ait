# ADR-117：终端配色查询与外观更新生命周期

状态：已接受

日期：2026-10-09

## 背景

桌面与 Web 终端的背景能随主题切换，但 OpenCode 等 TUI 通过终端协议识别深浅色。
共享 xterm runtime 拦截了 OSC 10/11/12 颜色查询及 `CSI ? 996 n` 深浅模式查询；
Rust PTY adapter 不提供客户端配色。应用因而无法读取实际显示的颜色。

此外，导航层的外观边界在主题变化时重新挂载整个 workspace。新建的 xterm 实例
丢失运行中 TUI 已开启的 DEC 2031 配色通知订阅，不能再向应用报告变化。

## 决策

- 显示端拥有与其实际 palette 有关的协议回复。共享 xterm runtime 放行 OSC 10/11/12
  和单参数 `CSI ? 996 n`，由 xterm 使用当前颜色回复；其余既有查询拦截保持原行为。
- DEC 2031 订阅、退订和主题变化通知继续使用 xterm 的实现。历史输出恢复的输入屏障
  阻止重放查询向 PTY 产生回复，不为应用注入历史输入。
- Workspace 是持续存在的导航屏幕，外观更新不重新挂载它。面板内的外观边界刷新
  非终端内容；终端通过既有 `setTheme` 更新颜色，保留实例、输出和通知订阅。
- 不增加 daemon 消息或跨 crate 依赖，不读取或修改 OpenCode 的主题配置。

## 后果

终端中的 TUI 可以读取实际浅色或深色 palette，并在订阅后接收运行中的主题变化。
daemon 无需假设所有客户端具有相同配色。此实现未新增跨客户端的回复所有权仲裁；
多个客户端同时观察同一 PTY 时仍需各应用处理现有多观察者行为。

端到端测试使用隔离 PTY 中的查询脚本验证深浅背景、双向通知和 xterm 实例保持；
浏览器测试验证颜色与模式回复、退订及历史重放抑制。协议参考见
[Contour 配色通知](https://contour-terminal.org/vt-extensions/color-palette-update-notifications/)。
