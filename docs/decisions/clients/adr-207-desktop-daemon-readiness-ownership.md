# ADR-207：桌面 daemon 就绪探测与进程生命周期分离

- 状态：已实现
- 日期：2026-11-01
- 关系：修订 [ADR-048](adr-048-paseo-desktop-rust-launcher.md) 的启动失败回收策略，以及 [ADR-128](adr-128-desktop-daemon-keep-running.md) 的探测、交接与接管失败处理。

## 背景

桌面原来在读取 `daemon ready` 日志后调用 `daemon.get_status`，任何错误都会走启动回滚，向子进程发送 SIGTERM，必要时升级为 SIGKILL。该查询依赖 Provider 可用性和共享业务任务额度；资源繁忙、连接断开或等待超时都不能证明进程已经无法运行。仅重试 `resource_exhausted` 会推迟关闭，不能修正生命周期判定。

## 决策

- 本次创建的子进程以 `daemon ready` 日志和带 Bearer 认证的协议握手确认就绪。PID 来自实际 ChildProcess；握手不请求业务能力，不调用 `daemon.get_status`。
- 一次启动／连接等待仍有期限。超时、认证拒绝或连接错误使本次调用失败，保留仍存活子进程的 PID、监听地址、凭据、启动时间和所有权。`status: errored` 表示该次连接失败，不能据此推断进程已退出；`ownedByDesktop` 与 PID 表达进程所有权。
- 后续 `start()` 继续读取同一子进程的日志进度或重新握手，不创建第二个进程。成功后清除错误；实际 spawn 失败或 exit 才清除子进程所有权。没有后台自动重启或无限等待。
- 停止、重启、禁用内置管理、删除自有本地主机，以及按退出设置停止服务，仍是明确的生命周期操作。它们按所有权执行，不以 readiness 成功为前提。
- 开启退出后保持运行时，只要自有进程仍存活且交接凭据完整，即使本次探测失败，也允许保存交接记录并释放句柄。缺少交接信息时沿用既有退出失败处理。
- 接管前仍须用保存的 token 请求 `daemon.get_status` 并核对 PID；不能将一次握手当成跨桌面会话的 PID 证明。探测失败保留 `desktop-daemon.json`、返回错误，不接管、不发送信号、不启动竞争进程。只有 PID 已退出、认证响应证明 PID 不符，或者成功接管／完成原有监听变更处理时才删除记录。

## 后果与验证

业务负载不再决定新启动 daemon 的存活。长时间未就绪的进程需要重试连接或通过现有停止／重启入口处理；退出后的身份校验暂时失败时，桌面保持失败状态并允许重试。若保存的 PID 被其他进程复用且无法核验身份，也不会自动杀进程或丢弃记录。

`apps/desktop/src/daemon/rust-daemon-readiness.test.ts` 使用隔离的真实子进程与 WebSocket 夹具，覆盖业务繁忙、握手无响应／拒绝／断线、日志就绪超时、同 PID 重试、显式停止／重启、退出交接和接管失败保留记录。现有生命周期测试继续覆盖 spawn 失败与未验证 PID 保护；客户端管理开关测试覆盖错误状态下停止自有进程。
