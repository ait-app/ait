# ADR-223：桌面多窗口与 Workspace 状态归属

- 状态：已实现
- 日期：2026-11-09

## 背景

Desktop 已能创建多个 Electron 窗口，但 Workspace 菜单没有对应入口。现有项目打开接口只传目录，不能保留远端主机和 Workspace 身份。各窗口分别持有前端 store，却整体覆盖同一份本地存储，因而操作不同工作区也可能丢失另一窗口已保存的布局或草稿。附件清理原先也只考虑调用窗口的引用。

## 决策

- 保留单实例 Electron 主进程及现有 daemon 生命周期。多个窗口共享账号、主机与后端业务数据，每个 renderer 保有自己的导航、标签页、布局和连接资源；关闭一个窗口不退出其他窗口。
- Workspace 右键和三点菜单通过 `openNew({ workspace: { serverId, workspaceId } })` 创建额外窗口。主进程只接受经过校验的结构化身份，构建应用内初始路由，不接受任意 URL。原有空窗口、项目目录打开流程保持兼容。
- 布局、面板、浏览器记录、聊天草稿与评审草稿的持久化，在同源 Web Lock 内读取最新快照，只应用本窗口相对上次读取／成功保存快照的变化。工作区、浏览器或草稿字典按记录合并，删除同样作为变化保存。原生客户端在单 JS runtime 内串行执行。
- 各窗口的当前布局不互相同步。同一工作区在两个窗口中可以有不同的标签页和布局；重启或新开窗口读取该工作区最近一次保存的布局。不同工作区的布局保存不会互相覆盖。
- 聊天草稿通过存储事件及窗口重新获得焦点同步。刷新先发布编辑器尚未入库的输入并完成本地检查点，在存储锁内最终校验前再次发布，检查本地状态是否变化；中文输入法组合期间、读取时又有新输入或保存失败时保留本地输入并暂缓刷新。应用外部快照更新实际输入框而不触发反向保存，并同时更新保存基线。同一草稿并发编辑以最后一次成功保存为准，不提供协同文本编辑。监听由应用根组件生命周期注册和清理。
- 已保存数据的版本高于当前支持版本时，拒绝读取／覆盖并保留原始数据。旧版本数据继续走各 store 原有迁移。
- 主进程按窗口登记附件引用及创建中／尚未上报的附件，清理时使用引用并集并串行处理文件操作。窗口关闭时将其引用保守保留至主进程结束；下次启动由持久草稿恢复引用后继续正常回收，以免其他窗口的旧快照误删图片。

## 后果与验证

本次调整位于客户端，不改变 Rust 领域边界或后端连接协议。Desktop 以安全应用 origin 使用 Chromium Web Locks；不为每个窗口启动新 daemon 或拆分账号 profile。现有账号 Relay 的进程级连接额度仍然适用。

定向测试覆盖目标校验、路由编码、两种菜单、新旧窗口入口、不同工作区并发保存、同工作区独立显示、删除不被旧快照复活、草稿刷新期间的新输入保护，以及多窗口附件清理。Electron 集成检查使用临时 profile 和隐藏窗口，不接触用户账号或运行中的 daemon。
