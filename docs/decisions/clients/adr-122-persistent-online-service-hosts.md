# ADR-122：在线服务主机进入客户端持久注册表

- 状态：已实现
- 日期：2026-10-10
- 关系：修订 [ADR-074](adr-074-account-host-relay.md) 的单台临时选择，以及 [ADR-076](adr-076-android-account-relay.md) / [ADR-084](adr-084-ios-account-relay.md) 的客户端主机恢复行为；账户登录和主机发布仍按 [ADR-083](adr-083-online-service-host-sync.md) 分离。

## 背景

账户 JWT 已保存到平台安全存储，但显式选择的在线服务主机只存在于 HostRuntime 内存中。
主机持久化过滤了 `accountRelay` 连接，读取 schema 也不支持该类型。切换主机移除上次选择，
重启只恢复登录凭据，因此用户需要重新添加主机。中继授权还依赖单一 `selected`，仅保存记录
无法使多台主机在重启后独立恢复。

## 决策

- 显式添加的在线服务主机使用既有客户端 HostRuntime 注册表 `@paseo:daemon-registry`，由 AsyncStorage 持久保存。`accountRelay` 连接保存规范化服务地址 `center` 和 `hostId`；主机沿用稳定 `serverId`、名称、外观、创建时间和连接偏好。账户 JWT、密码及中继票据不写入这类连接记录。
- 同一 daemon 的在线服务连接与已有 TCP / SSH / 本机连接合并，保留用户命名和外观。再次添加相同连接不创建重复主机。不同服务的连接身份包含服务地址，避免相同 host ID 混淆。
- 添加命令等待存储写入成功才返回并导航；写入失败向用户报告，允许重试。注册表写入按顺序执行。正常删除先完成存储写入，再移除运行时记录。
- 读取注册表时逐条校验；单条损坏或已经停用的连接记录不清空其他有效主机，清理后的注册表重新保存。
- 启动先恢复保存的主机及缓存目录。平台账户恢复上线后，只激活服务地址匹配的中继连接；未登录或登录其他服务时记录仍可见，不发起该服务的连接。在线主机发现和账户状态事件只更新连接可用性，不自动添加发现的主机，也不重新创建用户删除的记录。
- `selected` 表示账户界面最近的显式选择。每条中继访问及独立下载都携带保存的服务地址，平台账户管理器校验当前账户、客户端节点和服务地址，再向中心申请一次性授权；中心继续校验主机访问权限。访问不依赖单台 `selected`。切换选择不关闭其他主机的传输；登出、后台暂停和停机仍关闭传输。
- 退出登录只停用中继连接，保留客户端主机记录。删除主机从注册表和 HostRuntime 中移除该主机。账户界面的断开操作只删除最近选择主机在当前服务下的连接，保留该主机已有的直连配置。这些操作不停止远端 daemon 的在线服务发布。
- 同一主机同时具有直连和中继时，文件下载使用当前实际连接，携带中继连接对应的服务地址。

## 后果

Desktop、Android 和 iOS 可以保存多台明确添加的在线服务主机，并在客户端重启、重新登录后
独立恢复访问。更换服务或账户失效不会删除主机配置。账户权限仍以中心即时授权为准。

旧实现从未保存的临时主机没有可迁移记录，用户需重新添加一次；升级不会自动导入发现列表。
桌面 `account-node.json` 与移动端 SecureStore 的凭据存储边界保持原有职责。
