# ADR-083：在线服务登录与逐主机同步分离

- 状态：已实现
- 日期：2026-10-05
- 关系：修订 [ADR-074](adr-074-account-host-relay.md) 的登录入口与桌面自动发布行为，沿用 [ADR-076](adr-076-android-account-relay.md) 的凭据归属。

## 背景

添加连接页同时显示登录表单、账户状态和主机列表，连接方式缺少统一层级。
账户设置混入每台主机的概览，但登录实际只能自动发布桌面本地 daemon，无法单独同步 TCP 或 SSH 主机。

## 决策

- 添加连接页以同样样式呈现直接连接、Online Service（在线服务）和 SSH，欢迎页使用相同名称和顺序。在线服务进入二级页面后再显示登录和在线主机选择，支持返回；关闭页面清空表单。
- 应用设置增加「在线服务」，负责登录、服务地址、账户连接状态和退出登录。主机概览移除账户面板。
- 每台主机的连接设置增加「与在线服务同步」。已登录客户端可以将当前 daemon 接入该账户，并显示状态或停止同步。桌面登录不再自动发布本机。
- `api` 在既有经过鉴权的业务 WebSocket 上实现 `relay.status.request`、`relay.start.request` 和 `relay.stop.request`。这些方法归属传输层，不修改固定的 Paseo 方法目录，也不让 `metadata` 依赖 `relay`。
- 状态接口返回当前 daemon 的 server ID、instance ID、平台及非秘密连接状态。客户端校验 server ID 后，由平台账户管理器注册该身份并取得一次性控制票据。daemon 继续使用自己固定的本地地址和 Bearer，用户 JWT 不发送给 daemon。
- 共享账户管理器分别维护每台已同步主机的节点租约，最多 16 台。每台租约保留其原账户授权与独立请求集合，每 20 秒续租，daemon 重启后替换原实例的租约。停止同步只撤销单台租约。
- 客户端退出账户只释放客户端节点与当前绑定 daemon 的租约，并停止绑定 daemon 的控制连接。其他 daemon 不删除租约，不停止续租；即使客户端尚未重新登录，也可补发这些 daemon 的控制票据或主动停止其同步。客户端切换账户或服务不转移既有 daemon 的租约归属。
- 客户端在离开设置后继续检查已启用主机的控制状态并按需发放新票据；不重放已发送的业务写操作。非秘密账户快照列出仍受管理的 daemon ID，界面只在退出时清除绑定 daemon 的同步状态。Android 进入后台暂停客户端发现与访问，不主动撤销远程主机租约。
- 租约续租仍由运行中的平台账户管理器负责，使用中心既有授权期限。关闭应用不主动撤销其他 daemon 的租约，但进程停止或授权失效后无法继续续租；重启应用需要再次启用主机同步。本次不引入 daemon 的持久账户凭据或新的中心端授权协议。
- 旧 daemon 未实现这些方法时显示升级提示。浏览器和 iOS 沿用原来的直接连接能力。

## 后果

登录与主机上线各有独立入口。本机、TCP 和 SSH 连接使用同一同步流程，手机仍只发布显式选中的远程 daemon，不作为工作主机。
客户端登录生命周期与其他 daemon 的租约生命周期分离。平台负责续租与一次性授权，daemon 负责控制连接和反向数据连接；JWT 始终留在平台账户管理器内。

测试与覆盖率见[PR 验证报告](../../reports/clients/online-service-host-sync-validation.md)。
