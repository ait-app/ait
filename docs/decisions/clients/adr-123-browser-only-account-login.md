# ADR-123：客户端仅保留浏览器统一登录

- 状态：已实现
- 日期：2026-10-10
- 关系：修订 [ADR-086](adr-086-authing-native-login.md) 的旧密码登录兼容策略；沿用其浏览器回传、安全存储和主机同步边界。

## 背景

移动端和 Desktop 已支持统一浏览器登录，但仍保留原 AIT 邮箱密码表单，且在服务能力发现失败时自动显示该表单。客户端需要统一使用浏览器认证。

## 决策

- Android、iOS 和 Desktop 共用的账户界面仅显示「登录 / 注册」，删除旧密码切换入口、邮箱密码输入框和对应文案。
- 删除移动端账户命令与 Desktop IPC 的 `account_login`，以及共享客户端的密码登录方法；客户端不再调用 `/v1/auth/login`。
- 登录按钮直接发起浏览器登录，服务能力检查在共享账户管理器内部执行。删除仅用于界面切换的能力发现桥接命令；未启用统一登录的服务提示升级或更换服务地址，网络错误允许重试，不回退到密码登录。
- 保留浏览器登录的 PKCE、取消和超时处理，以及已有会话恢复、退出和逐主机同步语义。浏览器连接模式的账户能力范围不变。
- 旧账号的显式绑定仍由 Web 控制台处理；客户端不负责接收旧密码，也不修改中心服务的认证接口。

## 后果

新登录要求中心启用 `authing_enabled` 和 `native_login_enabled`。已保存且仍有效的会话可继续恢复；尚未绑定统一登录的旧账号需先在 Web 控制台完成绑定。无需更改 Rust daemon、数据库或系统浏览器回调注册。
