# ADR-160：清理旧公钥中继协议与测试残留

- 状态：已实现
- 日期：2026-10-19
- 后续：[ADR-164](adr-164-remove-workspace-service-proxy-urls.md) 移除三种服务代理 URL 及对应的兼容测试，在线中继继续使用现有回环转发。
- 关系：完成 [ADR-061](adr-061-app-ait-e2e-remove-relay-plugin.md) 暂留的旧协议清理，延续 [ADR-127](../daemon/adr-127-remove-daemon-pairing-offer.md) 的配对入口移除；[ADR-074](adr-074-account-host-relay.md) 的账户中继继续使用独立协议。

## 背景与决策

旧公钥中继的连接实现与配对入口已移除，共享协议仍导出没有生产调用方的默认中继地址、协议版本、URL 构造与 TLS 推断函数，以及配对 offer schema 和 URL 解析器。本次删除这些导出、专属测试与验证脚本中无用的 offer 别名，结束暂留。

HostRuntime 测试在历史迁移时将旧连接改为 `directTcp`，却保留了旧域名、公钥样例、配对描述和变量名。本次整段删除“重新配对更新 daemon 公钥”的废弃用例，不将它改写为另一种连接或认证行为。旧 relay 协议专属测试也随实现整段删除。

## 保留的测试现场及依据

以下夹具保留原始域名、连接 ID、变量名与样例值，并在代码中说明用途；不通过替换示例域名或重命名将旧 relay 痕迹隐藏。

| 位置                                                                    | 保留理由                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `host-runtime.test.ts` 的 `makeHost` 及各用例中的同一地址、延迟表和断言 | 验证首个成功探测、慢探测不阻塞、心跳延迟、探测退避、连续胜出后切换、瞬时延迟抑制、过期切换结果和目录状态等当前行为。连接类型早已是 `directTcp`，连接与 ping 由注入的假客户端完成；保留测试可防止这些通用行为回归，旧地址用于保留来源现场。 |
| `host-runtime.test.ts` 的选中连接重连用例                               | 验证正在重连的客户端不会被额外探测客户端替换；客户端和探测均由测试注入。                                                                                                                                                                   |
| `host-runtime.test.ts` 的双主机 AppState 用例                           | 验证 inactive/background 保持重连、回到 active 时恢复；两个客户端直接注入，任何新建连接尝试都会让测试失败。                                                                                                                                |

这些保留项不验证旧 relay service 可用，也不为旧协议提供连接入口。

## 保留边界

- 共享客户端继续拒绝旧 relay URL；存储恢复继续识别并丢弃旧 relay 连接，保留同一主机的有效直连配置。
- 当前账户中继的主机发现、授权与 transport 保持原有协议。
- 固定上游契约快照与历史报告保留为来源证据，不代表当前支持旧协议。

## 验证范围

定向验证连接 URL、HostRuntime、服务链接、旧连接存储丢弃、旧 relay URL 拒绝和当前账户中继连接配置，并检查共享协议构建及客户端类型。没有 Rust 代码变更，不运行 Rust 测试。
