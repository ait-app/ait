# ADR-132：管理网站中的浏览器客户端

状态：已实现。日期：2026-10-11。

## 背景

AIT 的桌面、移动端与 Web 已共用 Expo 界面，但账号中继此前仅有原生和桌面适配。
ait-server 网站需要提供浏览器工作界面，并复用已有的同源网页登录。

## 决策

- 沿用 Expo 的 Web 导出；`AIT_WEB_BASE_PATH=/client` 设置路由与资源前缀，
  `EXPO_PUBLIC_AIT_CONSOLE=1` 启用网站账号适配。默认独立 Web 开发与 Electron 构建行为保留。
- 浏览器仅提供在线服务入口，欢迎页和添加 Host 不提供直接连接与 SSH；不发布本机 runtime。
- `browser-account.web.ts` 读取同源管理后台的 `ait.access-token`，先验证 `/api/v1/me`，
  再用共享 AccountSessionManager 管理纯客户端节点。统一登录由 `/login?client=1` 的网站完成，
  不复用原生 PKCE 回调、不在 URL 或构建中携带凭据。刷新和浏览器重启保留服务端有效期。
- 浏览器节点由 Web Locks 分配可复用槽位，标签页独占节点；关闭页面只释放运行时资源，
  显式退出才清除当前登录。存储变化关闭旧连接，网络故障保留凭据，拒绝/过期清除凭据。
- 复用既有中继握手、目标身份校验与下载状态机；浏览器连接适配为一次性票据 subprotocol，
  服务端校验精确 Origin。文件完成后以 Blob 保存，单文件上限 200 MiB。
- 网站普通登录默认进入 Client。设置侧栏增加仅托管浏览器可见的「管理」tab，
  通过同源 `/manage` 内嵌原管理界面；权限与管理路由继续由 ait-server 负责，
  使用同源会话，不通过 URL 或消息传递令牌。登录过期与统一登录在顶层页面处理。
- 网站构建、静态托管、Authing 回跳及 Origin 配置归 ait-server；界面与浏览器传输实现归 AIT。
  修订 ADR-074/076/084 关于浏览器仅支持直连的边界，不改变原生与桌面凭据存储方式。

## 后果

无需维护第二套工作界面。浏览器需要可用的网站存储及 HTTPS（loopback 开发例外）；
仅对网站启用的能力不会进入普通 Electron/原生构建。
浏览器下载当前缓存整个文件，超大文件仍需桌面版。电脑 Host 仍需在线提供 Agent、终端和文件。
