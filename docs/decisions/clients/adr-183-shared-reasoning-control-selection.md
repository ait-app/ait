# ADR-183：共享推理控件保留已选身份，未指定时显示“默认”

- 状态：Proposed（已实现，待 PR review）。
- 日期：2026-10-22。
- 范围：`apps/mobile` 中供 Web、移动端和桌面 renderer 共用的推理控件。
- 关系：补充 [ADR-034](../providers/adr-034-agent-config-session-events.md) 提出的“宿主配置与运行时事实分离”，
  以及 [ADR-041](../providers/adr-041-agent-controls-provider-inspection.md) 描述的原生 Agent 控制；
  本决策只规定客户端如何选择与展示推理等级，不改变 Provider 侧的配置校验与生效时机。

## 背景

此前，已有 Agent 和草稿的推理控件在遇到“缺失或无法识别”的选择时，
会直接用目录中的第一个选项来补齐。这带来两个问题：

1. 用户没有指定推理等级时，触发器按钮和下拉菜单都会显示目录里的第一个等级，
   但真正发出的请求里并没有这个等级——界面显示和实际行为对不上。
2. 已保存的显式 ID 如果不在当前目录中，同样会被换成另一个可见等级，
   用户看到的就不再是自己当初选的那一项。

另外，当显式 ID 恰好是 `default` 时，已有 Agent 会把它当成特殊的占位值处理，
同样造成展示与请求不一致。

举个例子：目录先列出 `off`、后列出 `high`，而且没有声明默认值。
此时用户未指定推理等级，界面应当显示“默认”，请求中的推理参数也保持未指定。
而如果原生选项 `default` 的标签是“Adaptive effort”，用户显式选了它，
界面就应当显示这个标签，请求里照常提交原始 ID `default`。

## 决策

- **显式 ID 按不透明身份对待**，包括字面值 `default`。它只表示“用户选的就是这一项”，
  不再被解释成占位符或默认值。显式 ID 的优先级高于目录声明的默认值；
  已有 Agent 若没有显式选择，则采用规范化目录中的 `defaultThinkingOptionId`
  （该字段本身也考虑了选项自带的 `isDefault` 标记）。
- **不靠目录顺序猜测已选等级**。当无法解析出具体 ID 时，显示本地化的“默认”标签，
  下拉菜单中不勾选任何选项。这个标签只是展示，不会额外生成一个名为 `default` 的合成选项。
- **解析出具体 ID 时**优先使用目录中对应选项的标签；若该 ID 不在目录里，
  就把 ID 本身格式化成回退标签，从而保住它的选择身份，不替换成其他可见等级。
- **展示逻辑只有一份**：已有 Agent 与草稿共用同一个推理标签格式化函数，
  触发器标签和下拉勾选也基于同一份解析结果，保证两者永远一致。
  草稿控件不再自己挑第一个选项，而是接收调用方已经解析好的 ID。
- **提交时按解析结果构建命令**：未指定推理等级时省略 `thinkingOptionId`，
  有具体选择时提交该 ID。展示层的回退只影响界面，既不会写回配置，
  也不会改动 Provider 的全局默认值。
- **职责边界**：共享控件只负责“选择解析 + 展示”；
  Profile 与创建表单如何初始化各自的默认值，仍由它们现有的逻辑负责。

## 后果

控件不再暗示请求中并不存在的推理等级，界面显示与实际提交保持一致。
即便目录过期或将来出现新选项，已保存的选择依然能原样显示出来；
至于该选择能否真正执行，仍由 Provider 的校验逻辑和原生实现决定。
这里的“默认”只表示控件当前没有具体等级可展示，并不保证某个有效的原生运行时等级。

协议、持久化格式和 Rust 侧边界都保持现有契约不变。
