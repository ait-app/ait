# ADR-087：Timeline 单项 768 KiB 与按字节分页

- 状态：Accepted。
- 日期：2026-10-06。
- 范围：Provider 展示投影与 Timeline 查询；修订 ADR-039 的单项预算。

## 背景

正常的 GitHub CI 日志工具结果序列化为 358,522 字节，超过原先 256 KiB 的展示条目
上限。存储返回 `ResourceExhausted` 后，AgentManager 关闭原生会话并记录通用执行失败。
这个上限是 Ait 的应用预算，不是 SQLite 的大小限制。

查询响应仍有 900 KiB 预算，中继单条消息仍有 1 MiB 预算。只提高存储上限，会使多条
大工具结果的历史页超限；原先按展示条数选择整页再报错的行为不够用。

## 决策

- 单个序列化 `NativeItem` 的上限提高到 **768 KiB（786,432 字节）**，包含 JSON 字段与
  转义开销。完成条目与流式条目共用一个常量；累计展示文字也采用相同的字节预算。
- 查询保留 **900 KiB** 整体响应上限，计入 Agent 快照、游标与其他元数据。请求的 `limit`
  是条数上限，`limit=0` 仍受字节预算约束。
- 正常大小的页沿用已有 Paseo 展示合并与分页行为。页过大时，在连续原始 source rows
  上选取能容纳的窗口，再投影该窗口：after 从前向后取，tail/before 从后向前取。
  根据实际覆盖范围更新游标与 `hasOlder`/`hasNewer`，后续查询可读取剩余 source rows。
- 不截断单项工具输入、输出或文字。跨页的工具 lifecycle 可以呈现不同阶段的快照，
  `sourceSeqRanges` 只声明本页实际覆盖的 source rows。客户端按 turn/call identity 跨页
  合并工具快照，包括被文字隔开的调用；保留更新的完成状态、输出、稳定 ID 与游标。
  交错 lifecycle 或过大的文字合并也能在 source 边界分页。
- 如果一个完整 source row 加响应元数据仍超过查询预算，明确返回 `ResourceExhausted`，
  不返回无法推进游标的空页，也不跳过该条目。

## 后果

不改变数据库 schema、依赖方向或 RPC 字段。旧库无需迁移；提高预算后的 daemon 可继续
读取旧数据。客户端请求、中继、发送队列与 Provider 自己的流式文字预算保持原值。

超过 768 KiB 的存储条目仍按既有失败路径处理。本次不加入大输出附件或分块协议，也不
改变失败生命周期。数据库查询仍先读取会话历史再做展示投影；未来提高到 MiB 级上限时
需要另行处理全历史读取、复制和传输预算。
