# ADR-219：共享套餐缓存与 Codex 查询进程

- 状态：已接受
- 日期：2026-11-08
- 基线：v0.2.0（5e50a7a0）。延续 ADR-119 的账号隔离与原生额度边界。

## 问题

Codex `prepare_usage` 在检查额度缓存前启动 app-server 并执行 `account/read`。
Codex 0.166.0 的首次账号读取包含工作区路由发现；进程内可缓存，但每次重启都会丢失。
本机连续普通 RPC 虽返回相同采集时间戳，仍各耗时约 12 秒。
中心每轮强制刷新也使共享额度缓存失效。

## 决策

- Host 缓存归 `AgentManager`，所有独立读取通道共享；Agent 缓存仍绑定 live session 生命周期。
- Provider 可以提供廉价的本地凭据代次 `usage_cache_key`。此键只在内存比较，不记录或输出其源材料。
  Codex 对有界 `auth.json`、`config.toml`、登录环境和路径求指纹；Claude 使用实际原生凭据源的 token 指纹。
  缺失、未知或不可验证的凭据源不走快读；Codex keyring/auto 配置继续通过原生身份检查，避免使用过时文件代表当前账号。
- 在原生准备前检查 Host 快照。60 秒内直接返回；60–300 秒返回原快照并按需启动后台刷新；超过 300 秒或首次读取等待刷新。
  错误快照最多复用 15 秒。保留真实 `fetchedAt`、`successfulAt` 和同账号 `lastSuccessful`，缓存读取不重写采集时间。
- 已验证的 provider/凭据代次最多一条刷新；整个 Host 最多四路原生查询。排队、准备和查询共用 25 秒截止时间。
  手动强刷等待新结果或加入相同代次的在途刷新。普通缓存命中不等待刷新锁。
  无法验证本地凭据的请求不合并，每次独立检查原生身份；同 provider 的准备到查询串行执行，防止替换另一请求已准备的连接。
  原生身份回退只复用同凭据来源的快照。已验证 source 的准备失败/超时独立缓存 15 秒，不继承未知身份的历史。
  RPC 取消不取消共享刷新；shutdown 停止接收新刷新，等待有界任务结束，再显式关闭并回收共享查询进程。迟到的旧账号结果不能覆盖新代次。
- Codex 复用专用于用量的 app-server 和账号元数据。凭据、配置、工作目录或临时环境改变时重新建立上下文。
  查询失败或取消使进程失效，后续重建或 shutdown 时显式关闭并 wait 回收。直接创建、恢复、临时环境创建的会话各自持有查询连接，关闭会话同时回收。
  不会复用聊天会话的原生连接，Host 查询连接仅由 Host 读取者共享。
- `unavailable` 不进入 RPC 列表；界面兼容过滤旧 daemon 的此状态。零额度、零余额和临时错误保留。
- 中心自动采集使用 `forceRefresh: false`，严格旧 daemon 不识别可选字段时只回退一次空参数请求。
  旧 daemon 的五分钟缓存继续按原有规则工作；中心轮询周期不代表原生观测时间。

## 验证与限制

定向测试覆盖缓存快读、刷新合并、断开连接、超时、账号代次隔离、原生进程复用与凭据变化。
本机真实 Codex 验证中，普通缓存读取和强刷后读取均为 3 毫秒；冷读约 19.8 秒，强刷约 7.2 秒。
这说明缓存快读已绕过原生调用，不保证首次启动或上游网络请求的固定延迟。

Test coverage：未测量，用户未要求覆盖率；如需测量，使用 cargo llvm-cov 对 provider 用量相关测试单独运行。
