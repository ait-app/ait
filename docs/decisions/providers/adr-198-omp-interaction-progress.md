# ADR-198：OMP 交互等待期间持续发布事件

- 状态：Accepted
- 日期：2026-10-28
- 修订：[ADR-190](adr-190-omp-acp-settlement.md) 的异步交互和 [ADR-194](adr-194-omp-settlement-reconciliation.md) 的状态核对。

## 背景

OMP 的文件和命令审批、插件选择、确认、输入、编辑器和结构化提问共用
`extension_ui_request`。原生命令可以等待对话回答后才确认接纳；宿主必须继续轮询，
才能把请求交给用户并送回答案。

Agent manager 在提交后、开始轮询前读取 runtime 信息。同步 `get_state` 或追加输入的
响应等待可能把对话留在 transport 缓冲区，形成宿主等命令、原生命令等用户的循环等待。

## 决策

1. OMP 正在处理已提交的回合时，`runtime_info` 返回同一实例最近验证的身份和配置。
   空闲时仍通过原生查询刷新信息；结算继续使用有回合关联的异步状态检查，不用缓存推断完成。
2. 追加输入写入后返回，按原生请求 ID 和所属回合异步处理确认。未确认请求最多 128 个，
   超限在写入前拒绝。当前回合的拒绝或协议错误进入现有失败路径，旧回合的迟到确认不影响新回合。
   写入成功不宣称模型已经消费输入；后续失败不会自动重发。
3. 所有可回答对话共用既有 permission 事件、待处理快照和响应端口。保留原生标题、
   选择项说明和输入 placeholder；不按工具、插件名称或标题判断授权。
   `editor` 携带显式 `multiline`，共享问答组件使用多行输入并保留换行。
4. Rust 的原生回复测试与 TypeScript 的 wire 校验、表单解析、答案生成使用同一组静态夹具。
   测试覆盖写入、执行、选择、确认、输入、编辑器和结构化 ask，以及取消和过期回答。

## 后果

交互进度修复归 OMP adapter，共享问答组件按显式标记支持多行输入；继续复用现有协议和调度逻辑。
运行中的 runtime 快照可能暂时落后于原生控制变化；它只描述最近验证的信息，不用于结算。
官方 OMP 的工具权限仍由用户选择原生选项，拒绝和取消均原样回传。
