# ADR-177：Codex 宿主异常重启后的继续执行与失败上报

- 状态：Accepted
- 日期：2026-10-21
- 部分修订：ADR-175 第 2 项；Codex 在原会话中尝试继续，其他 Provider 保持原恢复策略。
- 延续：ADR-046、ADR-144、ADR-162。

## 背景

真实故障中，OOM 管理器杀死 daemon 及其原生子进程，服务自动重启后，旧安装包仍把
已经失去执行进程的会话显示为 running。需要修复异常终止之后的任务恢复和错误上报。

## 决策

1. 重启时，对有有效原生句柄、未归档、非内部且没有待处理持久交互的 Codex running
   记录，向现有持久 FIFO 放入一次独立的继续指令。已有排队用户输入优先，不追加继续指令。
   身份由原生会话与最后输入时间生成，重复恢复不重复入队；不重新提交原始用户输入。
2. 沿用独立执行 lane、原生恢复接口和资源预算。先接回原会话并读取已到达事件：若原生
   工作已经继续或完成，使用原生结果；否则发送继续指令，要求核实未完成工具操作，并避免
   重复已经完成的任务。恢复连接期间仍保留 durable running，不能提前写 idle。
3. 继续指令与普通输入使用相同的 claimed／accepted／uncertain 屏障。接纳结果不确定时
   不自动再发，结束假运行状态并报告中断。缺少可恢复身份或不适合自动继续时，也写入明确错误。
   等待完成时，queued 和仍在接纳中的 claimed 前台输入都属于未完成工作，不能在连接期间
   因队列已出队而提前返回失败；不把 uncertain 或即时交互答复当作仍待接纳的前台工作。
4. 原生接纳或执行失败时，保留已有脱敏错误，不能用泛化的排队失败覆盖；原生已发布的失败
   不再重复发布。连接恢复失败时，将具体应用错误写入 Timeline、lastError 与 turn_failed。
   finish.wait.error 使用同一个 lastError，只有没有具体说明时才回退固定文本。
5. 恢复失败后保留原生身份和历史，后续 Continue 仍可重试。无须改动 RPC 字段、domain 类型
   或数据库结构。宿主内存和 cgroup 配置不属于本次变更。

## 后果

可恢复的任务正常继续；不能恢复的任务可见地进入 error，客户端不再只看到持续运行。
继续是在新原生进程中基于历史发起的一次新轮次，不声称已死亡的采样或工具进程能够原地复活。
模型仍需检查外部工具操作的实际结果，宿主不盲目重放工具副作用。
