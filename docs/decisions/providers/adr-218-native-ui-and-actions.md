# ADR-218：原生临时界面与拥有者操作

状态：Accepted。日期：2026-11-03。

## 背景

官方 OMP 18.14.0 RPC 已导出文本状态、文本 widget、编辑器预填、登录链接及部分
TUI 操作。此前原始事件透传没有对应产品入口。用户选择保持官方 OMP，补齐已导出操作；
未导出的任意 `custom()`、组件工厂、header/footer 和主题编辑不引入私有运行时补丁。

## 决策

- Provider adapter 通过 session port 提供连接范围的 `providerUi`。状态和 widget 按原生
  key 替换、删除；widget 保留编辑器上下位置；编辑器事件按 ID 去重并避开提交事务。
  数据仅进入 live owner snapshot，不写对话历史或离线 replica。登录链接必须由用户点击，
  限制 HTTP(S)，登录完成或连接关闭后清除。
  静态操作目录允许在未恢复会话时查看；只有显式执行操作才恢复原生所有者。
  创建回执也移除临时界面，防止编辑器草稿或认证链接进入持久化创建记录。
  模型角色校验复用同目录已发现的有界目录，不在每次设置变更时再启动原生 Agent。
  OMP 成功模型目录按目录与运行环境隔离、有界淘汰；适配器声明成功目录不按时间过期，
  普通读取、角色校验与创建会话复用已完成发现的候选。其他适配器保留原有成功目录时效。
  OMP 同一目录与环境的元数据启动使用异步锁合并，等待者复用刚完成的探测；之后的显式刷新
  仍重新读取原生目录。目录内容版本同时包含功能候选，角色标签或默认值变化也会触发菜单更新。
  前端模型相关页面进入、模型/角色/思考强度菜单打开与选择、模型查看和诊断触发后台刷新，
  保留旧目录供立即展示与操作；同一 Host/cwd 并发访问共用一次刷新，冷启动加入已有发现任务。
  没有已完成目录的周期刷新；隐藏、禁用与断连面板不发起访问刷新。未完成发现继续短暂轮询。
  前端刷新不等待原生结果，不清除目录或使无关输入、操作进入等待态；显式手动刷新保持可用。
  刷新失败保留上次成功的模型、功能和时间戳，三十秒后允许重试；冷启动失败仍显示真实错误。
  后台刷新更新目录；下一轮原生启动仍通过原生模型选择核对。各操作独立等待并保留旧结果，
  临时界面只订阅自己的状态及工作目录，避免无关 Agent 更新触发重绘。
- 适配器发布语义操作目录及声明字段。客户端提供选择、填写、执行、错误重试和文件下载，
  不复制 OMP 插件业务逻辑。`agent.native_action.request` 只执行目录中的操作，拒绝额外
  字段、任意 RPC 类型、宿主工具替换和事件过滤修改。
- 操作在已有 Agent owner lane 提交；最终 receipt 与 session 借用分离，最多八项，
  等待期间持续交付原生问题、审批和事件。子任务控制必须先确认其属于当前原生 registry，
  不接受任意日志路径。关闭连接释放等待者。
- 分支、fork、树导航、handoff 和新会话要求没有前台输入，并阻止重叠变更。原生完成后
  刷新 runtime、句柄和当前分支投影；拥有者持久化观察结果后才释放成功 receipt。
  恢复、导入和切换已有会话继续使用 Ait 已有生命周期入口，避免第二个原生会话所有者。
  OMP 无摘要树导航只改变内存叶节点，因此读取官方 `get_entries.leafId` 投影当前分支，
  在 Ait 持久句柄记录目标、叶节点和原生日志末项。恢复时通过官方导航接口重新定位并核对叶节点；
  后续模型设置、模式、凭证标记和用量记录保留定位；新增消息、分支或其他结构记录使旧定位失效，
  官方关闭产生的 `session_exit` 仅是生命周期元数据，也保留定位。历史投影返回同一有效定位，
  避免只读恢复更新句柄时丢失它。此过程不修改原生日志文件。
- HTML 导出使用官方 `export_html`，输出到当前工作目录的唯一文件；下载复用认证文件通道。
  Electron 直连下载通过受信应用窗口的专用 IPC 使用原生下载流，限定单次文件下载 URL，
  与页面导航隔离；只有原生写盘完成才显示成功。每项传输独立等待和进度，拥有者关闭、导航、
  传输中断或停滞释放资源，未开始和并发数量均有界。原生保存位置对话框不计入连接等待预算。
  原生麦克风及听写入口明确标明作用于 Host，浏览器音频继续由已有语音通道拥有。
  Goal 使用官方 `goal` 的 get/create/resume/pause/drop，不替换 Ait 自身的目标执行器；
  仅创建接受目标和正整数预算，原生续跑继续遵循 OMP 的 continuationModes 配置。

## 后果

UI 控制不再伪装成助手正文。新增 UI 状态仍是 provider adapter 的投影，domain 不依赖
OMP 字段。未导出的 TUI 工厂仍明确排除，原版 OMP 的补全协商能力保持原样。
功能验收必须分别记录自动化、官方运行时和真实桌面结果，不能以原始 RPC 可透传替代验收。
