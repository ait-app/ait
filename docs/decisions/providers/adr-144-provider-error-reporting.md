# ADR-144：Provider 安全诊断与持久失败提示

- 状态：Accepted
- 日期：2026-10-13
- 延续：ADR-046、ADR-109、ADR-121、ADR-125、ADR-133
- Codex 展示说明由 [ADR-162](adr-162-codex-error-details.md) 补充：保留有界脱敏的原生原因与状态。
- 后续 [ADR-185](adr-185-native-provider-failure-details.md) 将有界脱敏的原生失败说明扩展到其他适配器，修订下文的固定展示策略；日志仍只记录结构化事实。

## 背景

多个原生 Provider 将错误统一成不带原因的 `AgentSessionError` 或 `AgentTurnEvent::Failed`。
OpenCode、Antigravity 已有部分失败说明，但公共执行层只发送终态事件，聊天不会显示持久
错误条目。Codex 的模型容量提示是 adapter 特例，原生历史校验也可能删除这类宿主通知。

## 决策

1. `provider::ports::diagnostics` 声明公共分类和可复制的安全诊断，包含来源、原生数字错误码、
   HTTP 状态和可空的原生重试状态。诊断只保留固定分类，不持有原生文本、请求、URL、
   工具参数或凭据。分类与日志实现留在 `provider`，不向 `domain` 添加依赖。
2. 各 adapter 提取原生错误；Codex、Claude、共享 ACP、DSH Web Host、Pi 的进程 stderr 持续
   读取，单行检查内存上限 32 KiB。结构化错误分类优先于受限的文本匹配，无法识别的原因
   使用通用说明。AGY 保留既有原生权限建议，OpenCode 只保留明确允许的固定原生说明。
   Codex 的 `httpConnectionFailed` 等宽泛连接包装允许由已识别的余额／额度原因和
   HTTP 状态细化；明确的上下文／额度结构化分类仍优先。上游流缺少完成事件时使用
   固定的“响应未完成”分类，不据此断言客户端网络故障。
3. 继续保留 `Unavailable`、`Failed`、`Rejected` 和正常取消语义。会话通过
   `failure_diagnostic()` 向协调层提供安全事实；共享执行层在关闭失败进程前保存原因，
   在失败终态之前提交一条 Timeline `error`，随后设置相同 `lastError` 和 `turn_failed.error`。
   每次失败有固定的待提交条目标识与时间，关闭或持久化重试不会生成重复错误通知。
4. 日志记录 Provider、错误来源、操作、分类、数字错误码、HTTP 状态、重试信息；最终失败
   日志额外带 Agent 与 turn 标识。相同诊断在每个连接内最多每 30 秒记录一次，期间重复
   次数在下一次记录或正常关闭时汇总。默认日志级别采用 WARN，已提交的最终失败采用 ERROR。
5. 宿主失败条目的保留标识为 `host:provider-failure:`，只对 `error` 类型生效。
   Timeline 校验原生前缀时排除这些条目；历史重写时在所属 turn 末尾保留它们，无法关联
   的通知保留在尾部。插件保留规则继续有效，既有数据不需要 schema 迁移。
6. 界面沿用共享 Timeline 错误通知组件，不增加 RPC 方法或 wire 字段。
   成功、取消、明确操作拒绝和单独工具失败不额外生成会话失败通知。
   原生声明正在重试的错误进入日志，不保存为最终失败原因；Ait 不因此重发用户输入。
7. 2026-10-19 补充：宿主异常重启遗留的 `running` 轮次使用相同保留前缀，先保存固定的
   重启中断通知，再提交错误快照。条目标识取最后用户输入时间；没有该时间时取 Agent 创建时间，
   避免 metadata 更新时间变化导致重试重复通知。无法恢复原生 turn 身份时不伪造关联。

## 后果

所有内置 Provider 都有公共最终失败兜底，同时可逐步扩展各自的结构化错误识别规则。
宿主错误通知可以跨断线、刷新与重启保留；原生历史仍由 Provider 管理，错误通知不会进入
模型输入历史。按 ADR-185，各适配器从明确的原生错误字段提取有界脱敏说明，通过
已有 `failure_message()` 展示；未识别分类也可保留处理后的原因。任意原生文本仍不能保证
完全脱敏，因此不扩大到任意诊断载荷，聚合日志仍只记录结构化事实。

本次不增加重试过程的临时 UI 状态或操作按钮；最终失败的建议包含在安全说明中。

## 验证与 Test coverage

定向回归覆盖公共分类与重复日志汇总、stderr 有界读取、各 adapter 原生进程夹具、失败
关闭重试、成功与取消、Timeline 追加／重写／重启，以及共享前端的错误与终态去重。
覆盖率未测量：用户未请求覆盖率测量；后续需要时按相关 Provider 与 Timeline 测试范围测量。
