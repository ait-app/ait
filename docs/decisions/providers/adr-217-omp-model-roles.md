# ADR-217：OMP 模型角色配置

状态：接受。日期：2026-11-02。

## 背景

Ait 原先只有当前会话模型和服务档位选择，没有 OMP 的 default、smol、vision、advisor
等模型角色设置。切换当前模型不能替代角色配置；原生 advisor、task、图片和语音能力会各自
解析角色。OMP 18.14.0 没有角色设置的 live RPC，但提供只读 JSON 查询和每次运行的配置覆盖文件。

## 决策

由 OMP adapter 查询原生已脱敏的 `config list --json`，只保留 modelRoles、modelTags、
cycleOrder；[模型预设](adr-221-omp-model-presets.md)另读取 modelPresets 与默认思考强度；通过 `models --kind all --json` 取得全类型目录。复用临时 `--no-session`
RPC reader 读取聊天模型的 webSearch 和服务档位。客户端不接收凭据、端点或原始配置。

通过既有 select feature 暴露 `modelRole.<role>`，覆盖 16 个内置角色，以及原生角色、标签和
轮换列表引入的自定义角色。候选种类遵守原生角色规则，vision 与原生一样接受 chat 模型，
图片能力在候选标签上标明；原生目录提供的推理档位使用 `provider/id:effort`。
非聊天模型只进入适用角色，不混入当前聊天模型选择器。

每个角色的 `native` 选项表示沿用 OMP 当前目录、profile 和环境的分层设置。原生继承值的
别名、模糊选择器与推理后缀只展示、不重写或自行解析。显式选择保存到 Ait 的会话配置，
通过私有临时 `--config` 文件传给 OMP，文件只包含显式 role 覆盖；不改全局或项目配置。
原有 Ait 表单偏好和 Agent profile 可以继续保存这些 feature。

协议保留完整角色 feature；展示上将角色与预设合并到既有模型选择/配置入口，而非通用
Features 菜单。用途角色默认收起，展开时复用原有候选与 setter；紧凑布局和 Profile 使用
同一分组，不另建配置来源。图标优先原生声明，再按稳定 feature ID 选择语义图标，
未知自定义角色回退为模型图标，不根据展示标签猜测能力。

角色修改遵循 Ait 的下一轮配置语义。运行中不改变已受理的输入；应用新配置前重新检查
目录并等待原生工作结算，关闭旧 writer 后恢复同一份已持久化的原生日志。当前聊天模型继续
使用独立选择器，角色 default 不强制覆盖已有会话的当前模型。
进程持有覆盖文件直到退出，恢复时从保存的 Ait feature 重建覆盖。
尚未恢复原生进程的会话通过现有只读 feature 查询补全候选，保留已保存值和推理档位，
不为打开设置而恢复对话。查询失败时仍保留可见的已保存设置。

目录失败、错误种类、未知角色及不支持的推理档位明确失败；验证失败不写入会话配置，
不关闭原 owner。角色及候选有大小预算，不通过截断生成不完整的可选项。

标准 ACP `configOptions` 同样提供这些角色选择，保留字符串值与原生候选，而非映射成开关。

## 验证

定向测试覆盖角色候选、非聊天类型、自定义角色、推理档位、私有稀疏覆盖、拒绝与继承恢复，
以及 Agent registry 重启后的配置和历史。官方 OMP 的临时普通扩展通过公开的
`ctx.models.resolve("@role")` 核实实际解析结果，不依赖源码补丁或模型推理。
恢复验收先用本地模型协议桩写入一轮真实日志，确认后续角色切换和恢复保持相同会话身份。
验证结果见 [交付报告](../../reports/providers/native-delivery-and-omp-roles-2026-11-02.md)。
