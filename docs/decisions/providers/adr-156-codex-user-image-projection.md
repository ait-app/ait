# ADR-156：整图输入与 Codex 用户图片的跨设备展示

- 状态：已实现
- 日期：2026-10-18
- 关系：延续 [ADR-098](../clients/adr-098-acknowledged-client-chunks.md) 的传输分块、[ADR-040](adr-040-native-session-import-refresh-context.md) 的原生历史所有权和 [ADR-125](adr-125-durable-timeline-projection-pages.md) 的持久展示投影；修订[图片输入修复报告](../../reports/providers/image-input-admission-2026-10-13.md)中的自动裁剪策略。

## 背景

Ait 之前把超预算图片裁成概览和多张局部图，并将坐标说明作为文本发送给模型。
这改变了用户输入的图片数量，Codex 历史投影又将裁剪图变成占位文字、把坐标说明合入正文。
发送端有本地原图缓存，另一设备只有文本投影，因此出现一张图片对应十条占位文字和内部说明的显示结果。

## 决策

- 传输分块由客户端与 daemon 处理，重组完整请求后才分发。Provider 不接触传输块。
- 每张用户原图对应一张完整的模型输入图片。删除发送端的自动裁剪、概览生成、图片分组和坐标说明；新会话、已有会话、新 Workspace 与 Workspace setup 使用同一准备逻辑。
- 继续按单图 base64 32 MiB 和完整序列化 prompt 63 MiB 判断预算。支持的格式在预算内保留原始字节，不因分辨率或长宽比而触发处理。
- 超预算静态图片先尝试整图无损编码，再以 0.94、0.88、0.82 的质量尝试 WebP；JPEG 沿用 JPEG。仍超限时等比缩小完整画面，最多缩小八次，无法满足预算就明确失败。处理中的输出面限制在 16 Mi 像素、最长边 16384；待解码图片保留既有 80 Mi 像素上限。格式转换也受处理资源限制，不截取局部区域。
- 多图总预算不足时，优先处理当前最大的静态图，保持图片数量和顺序；后续图片需要进一步缩减时重新读取原图，避免反复有损压缩。逐张读取、及时压缩超预算前缀，避免把所有超大原图同时留在内存中。原始附件及其预览不被覆盖。
- GIF、动画 WebP 和 APNG 在预算内保留，超出预算时明确拒绝，不转换成静态图。任一图片失败都会使整条发送失败，草稿与原图继续保留；每条消息仍最多 50 张原图。
- Provider 继续拥有原生历史到 Timeline 的转换。Codex 实时完成事件与历史重放共用用户图片投影。
- 用户消息增加可选 `imageSources: string[]`，保存图片 URL 或主机文件路径。内联 base64 使用既有私有、按内容寻址的 Provider 图片目录落盘，Timeline 不携带图片字节。
- 为兼容已经发送的旧会话，完整匹配旧版分片说明格式、图片位置及分组顺序时，仅保留各原图的全图概览作为预览，隐藏细节分片和模型用说明。不完整或无关文本保留；缺失图片来源时保留占位提示。
- 共享客户端通过既有鉴权文件 RPC 和图片预览生命周期读取主机图片，提供缩略图与点击查看。实时消息和历史加载均保留纯图片消息；发送端优先显示本地原附件。
- 不改写已经持久化的原生 prompt。旧展示投影可在既有原生历史校验中更新，沿用分代、游标和时间戳语义。

## 后果

模型与其他设备都以每张原图一张完整图片理解新输入；超预算时整图缩放会降低局部细节，需要原始像素的用户可自行选择合适的图片重新发送。
已经发送的旧会话在原生历史只有裁剪图时，其他设备仍使用旧全图概览，无法还原原图全部像素。
旧版本客户端不能消费新增图片来源，需升级客户端与 daemon 才能获得该显示行为。
整图发送策略适用于共享客户端的所有 Provider；本次跨设备用户图片展示接入 Codex，其他 Provider 的原生用户图片解析不在此次修改范围。
没有新增 crate 依赖、文件传输接口或数据库 schema。
