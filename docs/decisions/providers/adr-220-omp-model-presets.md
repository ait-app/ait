# ADR-220：OMP 原生模型预设与 Ait 模型控件

状态：接受。日期：2026-11-04。扩展 [ADR-217](adr-217-omp-model-roles.md)。

## 背景

OMP 的 model preset 包含整套角色和默认思考强度。只透传 `/modelpreset switch` 会修改原生
全局或项目设置，Ait 的已保存模型和私有角色覆盖仍可能继续生效，导致菜单与下一轮实际模型不同。

## 决策

OMP adapter 从官方 `config list --json` 发现预设，并通过 `--scope global/project` 读取完整的
所属层条目。同名项目预设整条覆盖全局预设，不把不同层的字段深合并。只保留模型配置白名单。

预设与模型目录共用 cwd/环境缓存和按访问后台刷新。成功解析按定义、目录、继承配置和默认思考
强度复用；失败在下次访问时重试。解析最多同时运行两个只读 reader，不清空可见的旧目录。

只读 `--no-session` reader 使用私有覆盖，交由官方 OMP 解析模型和思考强度。对显式 default，
临时公共扩展仅调用 `ctx.models.resolve("@default")`，通过普通通知返回模型身份；调用前核对
原生命令目录，未注册时拒绝，避免未知命令进入模型推理。它不依赖 `custom()`、内部模块或源码补丁。
检查失败不能把启动时自动回退的模型报告为成功预设。该扩展只加载在一次性 reader 中。

通过既有 select feature 的可选 metadata 提供完整配置。新建会话、已有会话和 Profile 在一次
本地状态更新或 `agent.config.apply` 中应用聊天模型、思考强度和全部角色。应用前由 Provider
校验，失败不写入；原有单字段入口同样经 Provider 的 grouped-selection 端口展开。
配置补丁只增加展开导致的模型、思考强度及 feature 差量，不覆盖并行到达的无关设置。

预设显示于现有模型选择器的配置区，紧邻默认收起的用途角色；不在通用 Features 重复列出。
当前模型、思考强度和角色仍是不同配置字段，合并的是入口而不是原生语义。桌面、紧凑
模型面板及 Profile 均复用原 setter，整套预设 metadata 的一次性应用保持不变。

应用为 Ait 私有快照：未指定角色以 overlay 的 null 阻断旧覆盖，已确认的原生选择器和默认思考
强度随会话保存。预设删除后已应用的会话仍可恢复；手动编辑角色后不重新套用旧预设，界面按实际
配置重新判断预设名或显示“自定义配置”。不修改用户全局或项目角色设置。

保存和删除是另外两项显式操作，通过隔离 reader 调用官方 `/modelpreset save/delete`，
只写指定的全局预设。保存使用 registry 中最新的下一轮选择，包含当前聊天模型和思考强度，
不使用运行中 owner 的旧副本。原生输出及写后检查共同给出结果；项目仍定义同名预设时明确报告
保留，不能声称完整删除。操作等待仅属于该操作，输入、审批及其他操作继续可用。
完成后后台刷新目录，保留旧候选直到新结果到达。

## 验证

定向测试覆盖层优先级、原生解析、缓存复用、失败拒绝、成套更新、单独编辑、删除后恢复、
保存最新选择及项目预设保留。官方安装测试使用临时配置和本地模型，不发送模型推理请求。
最新执行结果与桌面证据见[交付报告](../../reports/providers/native-delivery-and-omp-roles-2026-11-02.md)。
