# ADR-133：先显示持久 Timeline 页面，后台校验原生历史

- 状态：已实现
- 日期：2026-10-11
- 关系：延续 [ADR-091](adr-091-independent-session-execution.md) 的单会话原生历史所有权，以及 [ADR-125](adr-125-durable-timeline-projection-pages.md) 的持久分页索引。

## 背景

客户端首次打开 Agent 已请求最后 40 个展示条目，daemon 也按页读取展示索引。但 daemon 重启后的首次读取仍等待完整原生历史校验。有持久历史的长会话因此无法立即显示已保存的尾页。

## 决策

- `agent.timeline.get.request` 增加可选 `allowCached`。已有持久条目的查询可以走独立读取通道，不等待会话队列中的原生历史工作。
- 这类响应以 `historyNeedsRefresh` 表示本 daemon 进程尚未完成原生校验。缓存许可不等于历史已经最新；请求不携带该许可时继续保持原有校验语义。
- 客户端先应用页面、结束前台等待，再后台请求严格的 40 条尾页。每个连接和 Agent 合并并发校验请求；已有的会话通道继续负责原生读取去重、身份与 epoch 校验、原子替换和提交后事件发布。
- 上翻仍按 `before` 游标分批读取。恢复旧缓存后的增量请求保留现有有界分页及超量时跳至尾页的行为。
- 后台响应只提交到原连接代次和 Timeline owner；连接切换或 owner 替换后丢弃迟到响应。校验失败保留已经显示的页面，下次读取可重试。
- 没有持久条目的会话仍先导入原生历史；未完成的 rewind 原生替换标记禁止缓存路径。没有改变首次导入和完整原生历史校验的成本。
- daemon 用 `agent-timeline-cached-reads-v1` 宣告能力；客户端只向支持的主机发送新参数，旧 daemon 保持原流程。

## 后果

重启后的已有会话可以先显示持久尾页，原生服务的读取耗时不再阻塞该页面。短时间内显示的可能是 daemon 停机前的内容，后续严格查询与事件补齐或替换它。后台原生校验仍可能占用目标会话通道；没有承诺实际网络连接上的延迟数值。
