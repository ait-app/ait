# ADR-211：Pi 推理偏好在下一条 prompt 前应用

- 状态说明：已实现，评审中。
- 更新：2026-11-03。
- 范围：`crates/provider` 的 Pi 适配器与共享 Agent 管理器。
- 修订：[ADR-156](adr-156-pi-native-rpc-provider.md) 中"不支持 thinking"的表述。
- 扩展：[ADR-174](adr-174-pi-session-import.md)，补入记录的 thinking 偏好。
- 修订：[ADR-185](adr-185-native-provider-failure-details.md)：Pi 明确拒绝 thinking 控制时，
  改用按设置给出的说明，而不是原生错误措辞。
- 保留：[ADR-034](adr-034-agent-config-session-events.md) 中"请求配置"与"运行时事实"的分离，
  以及 [ADR-189](adr-189-pi-without-host-mode.md) 中"Pi 没有模式"的结论。

## 背景

Pi 原生提供模型和 thinking（推理强度）控制能力，但 Ait 的适配器此前会直接拒绝 thinking
偏好。现有的 Agent 配置通道可以独立于原生会话的实际生效状态，持久化下一条 prompt 想要的
设置。Pi 可能会钳制这些设置、在切换模型时重置 thinking，或者由扩展改变它，因此"保存下来的
请求"不能同时当作"运行时事实"。原生历史记录里带有 thinking 偏好，可以用于导入。

## 决策

沿用现有的配置持久化与"下一条 prompt 前应用"通道。创建会话和交互式恢复时应用显式指定的
模型与 thinking 偏好；之后的修改在下一条 prompt 之前生效，既不打断已被接受的回合，也不会
仅仅为了改配置而重新打开处于休眠状态的会话。不需要新增会话端口、管理器生命周期状态或
wire 字段。

thinking 选项的词汇、校验和运行时钳制都由 Pi 负责。可选级别按 Pi 1.2 已验证的七档顺序排列：
`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`；`thinkingLevelMap` 里的任意键或
映射值都不会凭空引入新级别。

不带 `reasoning: true` 的模型不提供任何 thinking 选项。对推理模型，`minimal`、`low`、
`medium`、`high` 默认提供，除非它们在 `thinkingLevelMap` 中的对应项被显式写成 null。
`xhigh` 和 `max` 各自要求 `thinkingLevelMap` 中存在显式且非 null 的条目，条目缺失或为 null
时不展示这两个选项。Pi 1.2 的原生级别里没有 `ultra`，即使映射里写了也不作数：它按"未知的
原始值"处理，交给原生钳制落到第一个受支持的级别，在有可验证的原生契约之前不对外展示。
安装测试覆盖了这个种子值和映射行为。

对所有 API，目录里要列出 Off，必须在 `thinkingLevelMap.off` 中显式给出非空字符串。条目缺失时
Off 按原生基线规则处理，只有目录提示做了保守处理：`openai-completions` 模型不展示 Off。
缺失的元数据可能让本来可用的原生控制项消失；反过来，显式映射对某个 Pi 版本或端点也可能
不够用。这个提示不代表投递能力。不要重新实现 Pi 的 provider、endpoint 或格式探测，也不要
把这个目录提示用于控制项校验、原生恢复或运行时事实。Off 的说明只表示"向 Pi 发出该请求"，
不承诺模型一定不再推理。

保存下来的和显式指定的 Off 请求，即使目录里不展示，也仍然是有效的主机意图：照常发给 Pi，
由 Pi 做校验和钳制。以 Pi 的拒绝为准，Ait 自己的推断不能阻止创建、恢复或 prompt 准入。
只恢复模型时使用原生元数据的级别阶梯，与目录过滤后的选项无关；目录默认值仍会把当前生效
级别钳制到可见选项内。其他 API 保持各自的基线选项。

RPC 返回的级别确认不能证明真正生成的模型请求或上游行为，所以 Ait 无法证明 Off 真的关掉了
端点推理。要给出这种保证，需要 Pi 提供权威的能力证据或投递证据，抄某个已安装版本的请求
构造内部实现并不能提供它。

在同一个临时的 `--no-session` 进程里，用 `get_available_models` 发现模型能力，并可选地用
`get_state` 读取当前生效的 thinking 级别。状态读取失败或超过 1 秒预算时，模型仍然可选，只是
thinking 默认值留空。模型的预选始终取目录的第一项，与这次可选读取无关，保持共享客户端
原有的回退行为。

每个模型的目录默认值都按"把当前生效级别钳制到该模型自己的可选项"来计算：级别受支持就
保留，否则先按 Pi 的阶梯往上找，再按降序往下找；遇到未知且不受支持的级别时使用第一个
可选项。级别缺失或格式错误、以及没有 thinking 选项的模型，默认值留空。下拉框的级别顺序
保持不变。

这样展示的默认值是有意把当前模型的生效偏好带到其他模型上的，不要求等于目标模型保存的原生
默认值。共享表单继续使用现有的 `defaultThinkingOptionId` 字段，不在客户端加 Pi 专属策略。
已保存的选择仍然优先于新发现的默认值。

请求的 thinking 偏好原样持久化，即使 Pi 把它钳制成别的值。生效级别另外发布在现有的
`runtimeInfo.thinkingOptionId`，包括来自扩展的通知，做法与 OMP 适配器一致。它表示 Pi 报告的
原生级别（包含 `off`），不是"已投递到端点"或"端点已停止推理"的证据；不要因为目录提示而屏蔽、
合成或改写它。只读导入同样投影出记录下来的原生 thinking 偏好，不要把这个值重复写进原生 extras，也不要在
客户端加解码逻辑。

目录过滤沿用现有的生效运行时身份；排队中的偏好会在下一条 prompt 前真正应用时变成生效值。
共享输入区和事实控件保持现有展示。运行时数据里未知的原生字符串，只要非空、不超过 512 字节
且不含控制字符就继续保留，与主机侧的选择上限一致。无效的原生通知直接忽略；无效或缺失的
快照级别不发布生效级别，也不会在切换模型时被重新应用。这两种情况都不会阻止回合。

排队中的 thinking 通知不能覆盖状态快照。在请求状态之前先清空已完成控制项积压的通知，之后的
快照覆盖它们，包括模型宣布的 thinking 重置。如果读取期间收到的通知和快照都给出了可用级别
却彼此不一致，先清空事件再重读一次状态；在重读预算内一直保留最近那条矛盾的通知，直到快照
与之吻合，或者被更新的通知取代。快照级别缺失或格式错误不算冲突。

同步最多读三次，仍然有歧义就拒绝准入，并且要在仅改模型可能覆盖原生偏好之前就完成这个判断。
创建、恢复和已被接受的工作在 thinking 仍有歧义时，保留最近一次已验证的快照；单凭这一点不算
会话失败。忙碌判断依据原生的流式与压缩状态，不把排队中的消息当成正在执行。响应之后到达的
通知仍然可以被常规轮询读到。模型身份变更的检测只比较运行时信息里发布的 provider 与模型 ID；
单是目录元数据变化，不发布不同的原生 thinking 事实。

创建和恢复时，在发送 thinking 控制之前，把显式的 thinking 偏好按所选或恢复模型的原生元数据
阶梯钳制，保存的配置里仍保留最初的请求种子。这也覆盖导入的历史：其最后记录的级别可能属于
更早的模型。能力未知时种子原样发送，交给 Pi 校验。

在活跃 writer 内，只改模型时，把保存的请求 thinking 级别（没有覆盖值时退回当前原生级别）
钳制到目标模型支持的阶梯后再恢复。之前生效时做过的钳制不能替换请求种子，这样回到支持该级别
的模型时能恢复最初请求的级别。钳制依据原生元数据阶梯，非推理模型则用 Off。只有在已知的推理
能力把所有可选级别都排除掉时，才跳过 thinking 控制。模型回复里没有推理能力信息时，种子原样
发送，由 Pi 校验或钳制；被拒绝则阻止该条 prompt，配置保持待处理，留待之后重试。

同时变更模型和 thinking 偏好时，先应用模型，再应用显式 thinking 偏好，显式偏好的校验与钳制
交给 Pi。不存在推断出来的 `thinking_delivery` 拒绝。原生确实拒绝了显式偏好的 thinking 控制时，
保留 `thinking_configuration` 诊断并阻止该条 prompt。适配器让 writer 保持可用以便用户改正，
但共享管理器在失败准入结算时会关闭它，之后的新 prompt 会恢复原生会话。这个已知诊断会替换
原始 RPC 错误，即使原生措辞看起来属于别的失败分类。

如果这种拒绝发生在打开或恢复阶段，就保留空闲的 writer 及其诊断，直到 prompt 准入通过持久的
prompt 失败路径报告该拒绝。被拒绝的 thinking 偏好单独匹配，不受其他配置字段影响；只要它没变，
就在这个保留的 writer 上继续阻止该偏好。仅仅改模型或 MCP 不会重新发送被拒绝的控制项。改正或
清空后的偏好可以在失败结算之前于同一个 writer 上应用，也可以在之后于恢复出来的 writer 上应用。

拒绝之后回读原生状态，这样成功的模型变更能发布它重置后的 thinking 级别。回读过程中发生传输
失败时，保留传输自身的诊断，让准入失败并退役该 writer，不能用配置拒绝把它覆盖掉。被拒绝或
因忙碌而结算准入、关闭 writer 之前，先采集运行时事实，其中包括被原生扩展改过的事实。重读
预算用尽后 thinking 快照仍有歧义时，也走这个准入终态失败路径。不会自动重发任何输入。

待重试的模型变更用"请求的模型"与"原生身份"比较，这样部分生效之后可以回退，也不会重置没有
变化的模型。控制项成功后最后一次状态读取同时充当 prompt 的顺序屏障；没有变化的回合只需要
最开始的忙碌检查。

模型和 thinking 偏好都没有变化时，不会撤销扩展在两条 prompt 之间做的修改。创建或恢复时如果
thinking 偏好未指定，就保留初始或恢复出来的原生级别，即使期间显式选择了模型也一样；在活跃
writer 里清空之前的显式偏好时，请求"把 Medium 按目标模型能力钳制后得到的受支持级别"，非推理
模型则用 Off，因为 Pi 没有取消设置的 RPC。

没有显式覆盖时，恢复和重置用的种子都只是尽力而为：原生明确拒绝就释放该覆盖，保留回读到的
原生级别，不阻止该条 prompt，也不在后续未变化的回合里重复发送这个种子。传输失败仍然让准入
失败。如果已知能力里没有任何受支持的基线，就不发送 thinking 控制。

## 后果

配置确认表示"主机意图已持久化"，不表示"原生已经生效"。原生拒绝会在该意图被应用时报告——
创建、恢复或 prompt 准入阶段。休眠期间清空配置只是释放覆盖，并跟随恢复出来的原生状态，不会
持久化一条一次性的重置命令。原生命令与主机存储仍是两个独立操作，沿用现有的生命周期和失败
行为。准入被拒绝走现有的终态失败路径；不引入自动重试，也不等待配置变更。

只读会话导入会连同模型一起投影所选分支上最新的 `thinking_level_change`。导入的级别沿用原生
运行时快照的同样上限，包括向前兼容的字符串；最后一级缺失或格式错误时，生效级别留空。

Pi 专属的控制项和回归测试都留在 Pi 适配器内。共享客户端、会话端口、应用服务和 wire 定义保持
现有契约；应用服务在拒绝或忙碌准入结算关闭 writer 之前采集原生运行时事实。不引入 daemon
专属的 thinking 实现。
