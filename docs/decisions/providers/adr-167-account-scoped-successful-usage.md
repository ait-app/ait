# ADR-167：用量缓存按原生账号与成功快照隔离

- 状态：已接受
- 日期：2026-10-20
- 关系：修订 [ADR-119](adr-119-native-account-usage-and-codex-speed.md) 的缓存策略。

## 背景

一次用量读取失败不应清空用户刚刚看到的数值，也不能把失败尝试时间写成成功更新时间。直接按 Provider 缓存历史，会在切换原生账号或恢复 Agent 时展示另一账号的额度。

## 决策

1. Provider 端口增加 `PreparedUsage`：先解析不透明的内存身份，再提供绑定同一认证上下文的惰性配额读取。命中缓存后不轮询配额。身份使用 SHA-256 摘要，只在内存比较，不能序列化或出现在诊断输出中。
2. Codex 在同一个原生 app-server 中先读账号，再读配额；Claude 捕获同一 OAuth 凭据；DSH API-key 路径捕获原生配置解析出的同一密钥。Ait 不刷新或管理这些凭据。
3. 主机与每一个 live session 各自拥有缓存，最多 64 个 Provider、有效期五分钟，强制刷新绕过有效期。会话关闭／恢复使用新缓存；停止的会话不回退到主机账号。当前身份缺失或变化时，旧缓存和成功历史一起失效。
4. 原生 API 未提供可独立确认的账号身份时仍返回当前配额，但禁用缓存复用与历史回退。当前涉及 DSH 原生网页登录路径、Antigravity 和默认未实现身份预检的适配器；不猜测凭据文件或合成账号 ID。
5. 最新报告始终保留本次 `available`、`error` 或 `unavailable` 结果。成功报告带 `successfulAt`；失败可以附带同一身份的 `lastSuccessful`，其中 `fetchedAt` 是那次成功的完成时间。缓存命中不更新时间。
6. 前端错误提示采用最新结果，数值条可采用成功快照并显示“上次更新”；过期重置时间明确显示已过期。旧值不进入侧栏 pinned summary。卡片按已展示顺序结算，避免并发完成顺序改变布局。

## 后果与验证

历史只在内存保存，不写入 SQLite、配置或客户端持久存储。原生凭据轮换可能保守地清除历史；无法确认身份时优先失效。旧客户端忽略新增可选字段，旧 daemon 无成功快照时仍显示原有错误。验证范围见[实施报告](../../reports/clients/paseo-0.12-port-2026-10-20.md)。
