# ADR-219：Pi 原生 slash-command 发现

- 状态：已接受（已实现）。
- 日期：2026-11-05。
- 范围：`crates/provider`；修订 [ADR-156](adr-156-pi-native-rpc-provider.md)。

## 背景

Pi 此前对宿主命令目录返回 `Unavailable`，尽管它的原生 RPC 支持 `get_commands`。输入框需要
扩展、prompt 模板和 skill 的原生调用名。共享的前端查询缓存已经控制 mount 和 focus 的重新
拉取。Pi 与其他 provider 一样，在每次后端请求时直接探测。

## 决策

- 用原生 `get_commands` 实现现有的 `AgentClient::commands` 端口，使用临时的
  `pi --mode rpc --no-session` 进程。不新增宿主协议或进程池。
- 命令发现规格提供写入限制时按其执行。当前共享的命令发现路径不提供限制，因此 slash 菜单
  探测不受限。
- 校验 provider 身份和工作目录，不校验会话配置。模型、mode、system prompt 和其他宿主会话
  设置都不影响这个发现进程。
- 保留原生名称，包括 `skill:` 前缀；把原生 skill 来源映射为宿主 `kind: skill`，其他来源映射
  为 `kind: command`。调用时通过现有的 prompt 路径发送 `/` 加上该名称和参数。Pi 从其原生目录
  中排除仅 TUI 的命令；Ait 依赖这一契约，由可选启用的已安装 Pi 测试检查。遵循其他 provider
  的 CI 约定：夹具测试在共享 Rust 套件中运行，已安装原生程序的测试默认保持 ignored，CI 不
  安装 Pi，也不跟踪其发布版本。
- Pi 仍负责加载资源和决定项目信任。Ait 既不自行扫描资源目录，也不授予信任。未定或未信任的
  项目不暴露受信任门控的项目资源；用户级命令仍可能出现。探测受信任目录会加载并执行其项目
  扩展，包括打开 slash 菜单时。
- 每次后端命令请求都用规范工作目录直接探测。不保留目录或命令失败，不合并请求，也不通过
  provider 专属的并发上限调度命令探测。RPC 启动、命令响应和优雅关闭共享两秒期限（或更短的
  已配置控制期限）；超时触发后台进程清理。命令探测和模型探测共享同一套生命周期：清理失败
  或超时只记录日志，绝不替换 RPC 答复或原生错误。版本发现先以自己的五秒上限运行（或更短的
  已配置控制期限），保留独立的成功缓存和五秒失败冷却。发现使用已配置客户端的环境。按环境
  划分的会话克隆各自拥有独立的版本缓存。低于 1.2 的版本在启动 RPC 之前就从该缓存结果中拒绝，
  包括前端重试和 focus 重新拉取时。
- 通过现有 provider 端口以 `Vec<Value>` 返回原生目录。Slash 命令请求走现有的直接查询路径，
  独立于模型目录。[ADR-091](adr-091-independent-session-execution.md) 的模型目录缓存、合并和
  并发上限保持不变。
- 所有 provider 沿用现有的共享前端查询行为：草稿命令查询无限期保持 fresh，已有会话的查询在
  60 秒后变为 stale。现有的三次重试分别等待一秒、两秒和四秒。没有 Pi 专属的 freshness 策略或
  窗口聚焦覆盖，也没有轮询定时器。
- 资源或信任变更在下一次后端请求时出现。前端查询仍需要一次 stale 重新拉取或应用重载。已在
  运行的会话在资源变更后可能需要重建。
- 最多接受 4096 个条目，名称非空、不超过 1024 字节且不含控制字符。缺失、无效或无法表示的
  名称（含空白、斜杠或引号）被省略，但不影响有效的同级条目。记录无效名称和目录校验诊断，
  不含原生负载。格式错误的外层结构和超量目录仍然失败。按原生顺序保留每个名称的首次出现。
  描述和参数提示中的控制字符替换为空格，两个标签都按 UTF-8 边界截断到 1024 字节。如果序列化
  后的目录超过 768 KiB（用有界计数写入器测量，不带 JSON 缓冲），就从所有条目中省略这两个
  标签并重新检查。仅名称和必填字段就超出该预算的目录被拒绝；绝不截断调用名或丢弃条目来适配
  预算。这在宿主的 900 KB 响应预算内留出余量，并计入 JSON 转义。原生传输的 2 MiB 帧上限仍然
  先适用。

## 后果与验证

宿主 slash 菜单可以发现原生 Pi 资源，无需创建持久会话或发起模型请求。每次后端请求都会启动
一次新的探测，包括同一目录下多个 agent 的请求；前端缓存限制了重复的菜单请求。命令失败可以
在下一次请求时立即恢复。非常大的目录仍可能触发原生帧限制或宿主目录限制。

Provider 归属的夹具测试覆盖映射、格式错误输入、配置无关性、全新探测与立即失败恢复、独立
目录探测、写入限制、调用名和负载边界。一个可选启用的已安装 Pi 测试发现隔离的原生资源，调用
取自该目录的名称，检查扩展副作用以及原生 prompt/skill 展开与 loopback 模型的对照，并验证
未信任与受信任项目的发现差异。它还检查原生 source 和 description 字段，以及宿主投影前
不存在 `/settings` 和 `/hotkeys`。不需要外部推理。
