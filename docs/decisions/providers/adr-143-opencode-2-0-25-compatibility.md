# ADR-143：OpenCode 2.0.25 兼容与 ACP 审批边界

- 状态：Accepted，2026-10-13。
- 范围：OpenCode adapter 与共享 ACP 审批转换；修订 [ADR-135](adr-135-opencode-catalog-readiness.md) 的最低版本判断。
- 保持：[ADR-115](adr-115-opencode-acp-provider.md) 的官方 ACP、原生认证、配置与历史所有权。

## 背景

此前仅实测 2.0.20 与 2.0.26，并将整个 2.0.0–2.0.25 区间拒绝。
逐版本核对发现，等待冷目录插件的修复
[fb72e25c](https://github.com/anomalyco/opencode/commit/fb72e25c0607b91b66775a8e401e4af718c690c2)
已包含在 2.0.25；2.0.25 到 2.0.26 没有 ACP 源码变化。
本机 2.0.25 的隔离真实测试确认可以使用既有 ACP 实现。

独立于版本判断，ACP 审批转换将展示标题按标识符验证，并将未保留的完整文件 diff
计入 64 KiB 预算。原生多行 shell 命令及大文件编辑因此触发 `Failed`，上层呈现 `AgentIo`。
另一个生命周期缺口是在 `session/new` 成功后选择模型失败，遗留空原生会话。

## 决策

1. 2.x 最低支持改为 **2.0.25**。1.x 保持原有行为，未验证的更早 2.x 仍返回升级提示。
   诊断不再断言所有旧版本都有同一种已证实缺陷。
2. 审批标题属于展示文本，保留换行与长命令；拒绝空白标题、NUL 和非字符串。
   `toolCallId`、选项 ID、已知审批类型的校验保持不变，不隐式批准或修改原生命令。
3. 64 KiB 预算约束实际保留的标题、工具 ID、输入与选项，验证后才复制到 UI 字段。
   未保留的 native `toolCall.content` 全文件 diff 由既有 8 MiB transport frame 上限约束，
   不再导致普通审批失败。未增加日志中的命令或文件内容。
4. 新会话的初始选项应用失败时，在原生声明 delete 能力的情况下，使用已有临时会话清理器删除
   该空会话。清理失败仍返回错误；重连仅用于删除，不重发 prompt。
   恢复会话的配置失败不得删除用户原生会话。
5. 不为异步插件目录添加固定等待时间、猜测模型、私有 HTTP 回退或模型调用重试。
   原生 ACP 尚无“所有异步插件模型注册完成”的信号，慢插件后续注册模型的限制仍适用于
   2.0.25 和 2.0.26。支持最低版本不等于承诺任意插件的初次目录都已完整。

## 验证与限制

真实 2.0.25 和 2.0.26 使用独立 XDG、原生数据库和 loopback 模型测试；保留正常模型发现、
配置确认、多轮、工具、审批、问答、取消、恢复和查询清理的回归。
默认无网络 ACP 夹具改为 2.0.25，使 daemon 集成测试也覆盖新的最低版本门槛。

完整证据、慢插件复现和 Test coverage 状态见
[兼容性检查报告](../../reports/providers/opencode-2.0.25-compatibility-2026-10-13.md)。
