# ADR-140：Codex MCP 超大字段使用展示预览

- 状态：Accepted。
- 日期：2026-10-12。
- 范围：Codex MCP 工具展示；修订 ADR-090 对超大 MCP 字段的处理。

## 背景

GitHub 版本比较工具正常返回的 MCP 结构化结果使单条 Timeline 序列化为
828,249 字节，超过 768 KiB 的存储预算。AgentManager 因展示写入失败关闭原生会话，
工具已经成功执行，用户却看到通用执行失败。提高存储上限仍会碰到查询和中继预算。

## 决策

- Codex adapter 在生成 MCP 卡片时，按序列化 JSON 字节数分别限制工具参数、结果和错误。
  参数与错误各为 64 KiB，结果为 512 KiB，给条目身份与其他字段保留空间。
- 在预算内保留原始 JSON 值与结构；超出预算的字段改为 JSON 文本前缀预览，明确标记
  `Output truncated; full output remains in the native transcript.`。预览保持有效 UTF-8，
  并为 JSON 再次转义后的大小留出预算。
- 大字段的大小检查和前缀采集在同一次有界序列化中完成，超限后立即停止，避免额外生成
  完整 JSON 文本。完整工具数据继续由 Codex 执行和保存，不修改其原生输入或结果。
- 实时 running/completed 卡片和原生历史读取共享同一转换，保留调用身份、状态、名称，
  使恢复和幂等写入得到相同预览。图片仍先按既有规则物化，MCP `_meta` 仍不进入展示。
- Timeline 存储、整页查询、中继预算和其他条目失败策略沿用现有实现。

## 后果

不增加 RPC 字段、数据库 schema 或跨 crate 依赖。超大 MCP 字段在 unknown 卡片中变为
可读字符串；正常字段继续呈现结构化内容。旧会话再次读取原生历史时也能生成有界预览。
没有大结果附件下载功能，完整数据需要从 Codex 原生记录读取。
