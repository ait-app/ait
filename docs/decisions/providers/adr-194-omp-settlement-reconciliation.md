# ADR-194：OMP 原生空闲状态核对与有界取消

- 状态：Accepted
- 日期：2026-10-27
- 修订：[ADR-180](adr-180-omp-native-rpc-provider.md)、
  [ADR-190](adr-190-omp-acp-settlement.md) 的结算与取消规则。

## 背景

正文输出结束不代表原生后台工作已结束，单个 `agent_end` 也可能先于重试或压缩。
此前 Ait 只等待 `prompt_result` 和 `session_settled`；通知遗漏后即使原生已空闲，
宿主仍保持 running。取消又同步等待 `abort_and_restore_queue` 回复，原生清理延迟会阻塞
该会话的停止请求和事件处理。

官方 OMP 18.12.6 的 `get_state.isSettled` 与结算通知使用同一原生判定，涵盖运行、
已接纳输入、消息队列、后台任务及待投递结果。它提供了同一执行进程的只读核对来源。

## 决策

1. 已接纳的活动回合在事件队列排空后，最多每两秒向同一受管 RPC 进程提交一次
   `get_state`；同一时间只保留一个检查。写入按现有 stdin 串行化，检查不阻塞
   ACP/宿主轮询或取消，不启动第二个原生进程。内部状态回复不进入原生扩展事件通道。
2. 检查记录宿主 turn 身份，回复只作用于该 turn；结束后迟到的回复不能结束下一轮。
   追加输入或原生重新开始工作时，已发出的旧查询失效，保留关联直到消费其迟到回复。
   只有原生 session ID 匹配、明确 `isSettled: true` 且没有矛盾的运行、压缩、
   排队或后台工作事实时，才允许补齐终态。缺少字段、查询拒绝或忙碌状态都不代表完成。
3. 已收到当前关联 `prompt_result` 时，状态核对保留其成功、失败或中断结果。
   若当前输入缺少关联结果，允许结果晚于第一次状态回复到达；至少间隔两秒的再次空闲
   确认仍没有结果时，以明确的协议失败结束，不能把未知结果冒充成功。
   没有可用状态事实时继续等待原生事件，不对模型执行设置静默期限。
4. 用户取消只等待中断命令写入，不等待原生清理回复。同一 turn 的重复取消幂等。
   继续处理原生消息、回调和关联回复，并以原生结算通知、关联结果或空闲状态确认取消。
   中断确认等待上限为五秒（不超过现有控制期限）；超过后保留明确失败原因，交由
   现有会话所有者关闭原生进程组并退出运行态。进程关闭仍有其既有的有界清理时间。
5. 未确认取消不伪造成功；输入不自动重发，原生历史不改写。确认失败后的再次输入
   走现有原生恢复路径。所有规则留在 OMP adapter 与其 ACP 桥接中，不增加公共协议分支。

## 验证

定向故障夹具覆盖遗漏结算、遗漏结果、后台工作、未知状态、停止回复延迟/遗漏、重复停止、
取消期限、跨轮次迟到回复、状态回复先于结果及不同原生会话的隔离。
同时核对宿主持久 idle、标准 ACP 终态与下一次输入。客户端回归覆盖 OMP 和 OpenCode
结束后被旧快照重开的四个入口。

安装版验证使用未修改的官方 OMP 18.12.6、隔离原生配置和 loopback 模型。
测试代理只在传输中丢弃结算通知、将结果的空闲标记设为 false，验证原生状态核对；
不修改 OMP 安装，不读取用户认证，不调用付费模型。

原生依据：[RPC 契约](https://github.com/can1357/oh-my-pi/blob/45c35e40c46166dc726ccc52f5d27f40f2449f99/docs/rpc.md)、
[空闲判定](https://github.com/can1357/oh-my-pi/blob/45c35e40c46166dc726ccc52f5d27f40f2449f99/packages/coding-agent/src/modes/rpc/rpc-session-settle.ts)。
