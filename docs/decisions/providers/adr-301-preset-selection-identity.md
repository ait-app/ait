# ADR-301：模型预设与普通模型的选择身份

## 背景

模型预设和普通模型可能使用相同的模型；多个预设也可以使用同一个模型。仅凭模型值
无法判断用户选择的是哪一个，因而模型列表可能把预设的模型误显示为普通模型已选。

## 决策

- 宿主为 Agent 持久化明确的预设选择身份，连同 Provider、作用域和来源区分同名预设。
  旧记录没有身份时不按模型值猜测。客户端只在确知所选身份时勾选对应预设；普通模型
  与预设的选中状态互斥。
- 选择预设通过可协商的类型化接口，在一次宿主配置更新中保存身份、预设配置和退出所需
  的独立设置基线。切换普通模型原子退出预设，仅恢复仍由预设管理的字段，保留用户独立
  修改及模式、权限等无关配置。新建 Agent 的预设选择也保留相同语义。
- 后续回合按已选身份读取当前预设内容，使在预设管理中保存的修改能够生效；找不到所选
  预设或来源不再匹配时明确报告，不能静默使用同名的另一预设。
- 运行中的回合保持已经接纳的配置，选择更新只作用于之后的回合。旧 Host 缺少选择能力时
  不伪造持久选择状态；新 Host 继续接受旧客户端的普通模型请求。

## 后果

切换普通模型不再隐式保留预设的角色或备选配置；使用预设时应在预设管理中修改其内容。
该选择是持久的跨客户端状态，不能仅存放在某一设备的组件状态中。
首条输入的去重与重启恢复依赖持久收据，Timeline 数据库升级至 schema v8 后不能直接由旧版本打开。
